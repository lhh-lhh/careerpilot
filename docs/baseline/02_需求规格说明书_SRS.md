## 1. 需求依据与约束建模

### 1.1 课程条款 → 设计约束（硬约束，不可协商）

| 条款原文要点 | 约束编号 | 可验证约束 |
|---|---|---|
| 技术组合二选一：HTML+CSS+JavaScript 或 HTML+CSS+React.js/Vue.js | `C-01` | 前端为 Vue 3 + TypeScript + Vite SPA，`package.json`、`src/` 组件树、路由表、`dist/` 静态产物齐备；不依赖业务后端，经本机静态 HTTP 服务加载（不是 file://） |
| 8 分钟内展示「开发背景、概要设计、关键技术、使用方法」 | `C-02` | 项目必须能用一条固定脚本路径在 8 分钟内走完四段叙事；演示数据可一键重置；每个展示点有独立入口 |
| 验收时间 12–14 周、15 周前交学号命名 PDF | `C-03` | 开发计划按课程周次排（见 06 §2），PDF 用学校封面模板，文件名 = 学号 |
| 评价指标：技术难度 / 界面美观度 / 报告演讲水平 | `C-04` | 每个指标必须有可展示证据（见 06 §1），不能只在报告里自称 |
| 六章大纲：HTML&CSS、Agentic Coding & JS、DOM/Event/FrontEnd、SPA、Web Application and Web Server、异步 JavaScript | `C-05` | 每章至少一个可指认的实现点（见 06 §1.4） |

> **合规边界**：条款限定的是**前端实现技术**，未要求或禁止任何后端语言。Python FastAPI 作为受限 AI Gateway（接入必做、运行按需） 不违反 `C-01`；但答辩叙事必须以 Web 前端为主角。

### 1.3 产品形态对照与差异化假设

| 概念参照（非实测竞品结论） | 常见能力假设 | 本项目关注的限制 | 本项目对策 |
|---|---|---|---|
| 高校自建 AI 就业平台 | 简历诊断、岗位推送、模拟面试、职业测评 | 多为独立工具堆叠；结果黑盒；治理端与学生端数据不打通 | 以原系统就业主链为骨架，AI 嵌入式分布；匹配结果逐维可解释（A3） |
| 商业招聘平台 AI 功能 | 简历打分、JD 生成、智能推荐 | 不面向高校管理场景，无辅导员/毕业去向/帮扶闭环 | 四角色协同 + 就业生命周期状态机（T5） |
| 通用 AI 聊天前端 | 多模型接入、流式对话、本地密钥 | 只是聊天框，无业务数据、无界面层次 | AI 能力落在具体业务页面，聊天仅作统一入口（A10） |

**一句话定位**：不是"又一个 AI 聊天框"，而是**把大模型能力嵌入毕业生就业全流程的可解释智能工作台**。

## 2. 干系人、用户画像与痛点

| 角色 | 典型场景 | 核心痛点（来自原项目与调研） | 成功标准 |
|---|---|---|---|
| **学生** `student` | 大四求职季，需同时改简历、找岗位、练面试、登记去向 | 不知道简历差在哪；岗位列表靠自己翻，不知为何推荐；没有低成本面试练习；投递后状态不透明；AI 建议不敢全信 | 得到"可解释、可采纳、可驳回"的具体改进与岗位理由，全程 5 分钟内能看到第一份诊断 |
| **企业** `company` | 校招 HR，发布岗位、筛简历、安排面试 | JD 写不清导致投递错配；收到的简历无法快速比较；面试反馈手工录入 | 一键生成结构化 JD，候选人按匹配维度排序并附摘要 |
| **辅导员** `counselor` | 负责数百名毕业生，需掌握进度、识别困难学生 | 只能看表格，无法发现"慢就业"；帮扶靠经验；政策咨询重复回答 | 驾驶舱直接给出预警名单与建议动作，帮扶形成闭环记录 |
| **管理员** `admin` | 维护字典、政策、账号、演示数据 | 原系统注册接口可匿名建管理员；无审计 | 权限边界清晰、AI 调用可审计、演示数据可一键重置 |

**非用户干系人**：课程评分教师（关注技术难度与界面美观度证据）、答辩现场环境（可能无网络）、学生隐私数据主体（简历含手机号、政治面貌等敏感字段）。

## 3. 需求基线：从原项目继承什么

依据 `01 §6.1`，把"原始项目需求设计逻辑"固化为本项目的**方向保留基线（并非所有辅助域必须本期全量实现）**：

| 基线 ID | 继承项 | 说明 |
|---|---|---|
| `BL-01` | 四角色与权限边界 | student / company / counselor / admin；每角色独立首页与可见模块 |
| `BL-02` | 就业业务主链 | 企业发职位 → 学生建简历 → 投递 → 面试 → 就业协议 → 毕业去向登记 → 统计 |
| `BL-03` | 辅助业务链 | 政策公告、就业规则、就业指导文章与预约、校园招聘会、满意度问卷、就业评价、就业帮扶、反馈建议、系统配置 |
| `BL-04` | 实体语义 | users / jobs / applications / interviews / resumes(+教育/经历/项目/技能/证书 5 子表) / policies / guidance / fairs / destinations / agreements / surveys / assistance / feedback / configs / 字典表 |
| `BL-05` | 状态语义 | 投递、面试结果、协议、去向审核、预约等状态及流转 |
| `BL-06` | 演示数据语义 | 参考原库12用户/6职位/9投递/5面试/6简历/3去向的关联语义，全部重新虚构并按10扩充；不复制个人字段 |
| `BL-07` | 项目大方向 | **毕业生就业管理与服务**，不是通用招聘网站、不是纯 AI 工具箱 |

**分期边界**：BL-03/04 保留概念与演进位置，不等于辅助域全量 CRUD 进入 MVP；基本协议、手工发岗、候选人授权、审核、帮扶、审计属于必做链，其他按 §5 和13。实体语义继承而非照搬原表/字段或个人数据。

**裁剪原则**：任何新增 AI 功能必须挂在 `BL-01..07` 的某个环节上；无法挂载的功能（如通用闲聊、AI 绘画）一律不纳入范围。

## 4. 业务流程与用例

### 4.1 主链（含 AI 嵌入点）

```
企业手工发布职位 → 学生简历[A1] → 推荐[A3] → 真实投递 → 企业真实面试 → offer
                                                                                ↓
学生独立练习[A2 模拟面试]（不改变招聘状态）                   协议双方确认 → 就业去向提交
                                                                                ↓
升学/创业/灵活就业/外部就业可独立提交 → 所辖辅导员审核 → A7统计/预警/帮扶
```

A6/A8 等生成增强可选，基础字段校验与主流程不依赖它们。详见10多实体迁移表。

### 4.2 用例清单

| 用例 | 主参与者 | 前置 | 主成功路径 | 关联需求 |
|---|---|---|---|---|
| UC-01 生成简历体检报告 | 学生 | 已填简历 | 结构化编辑 → 规则体检 + AI 诊断 → 逐条建议可采纳/驳回 → 生成新版本 | FR-S03/S04、A1 |
| UC-02 获取可解释岗位推荐 | 学生 | 有简历与职位库 | 选岗位 → 查看总分与 6 维贡献 → What-if 调整技能权重 → 一键投递 | FR-S05/S06/S07、A3 |
| UC-03 完成一轮模拟面试 | 学生 | 选定目标岗位 | 生成题本 → 逐题作答（文字/可选语音）→ 追问 → rubric 评分 → 报告与成长曲线 | FR-S08/S09、A2 |
| UC-04 发布岗位并筛选候选人 | 企业 | 企业已认证 | 手工填写 JD（A6 可选）→ 发布 → 候选人按匹配度排序 → 摘要卡 → 邀约面试 | FR-C02/C03/C04、A6 |

| UC-08 演示环境复位 | 管理员/答辩者 | 无 | 一键重置种子数据、切到 REPLAY 态、清空 AI 缓存 | FR-A05、NFR-09 |
