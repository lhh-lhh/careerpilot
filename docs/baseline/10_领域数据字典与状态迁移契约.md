# 10 · 领域数据字典与状态迁移契约

> 路鸣职引 CareerPilot · 开发基线 v1.5 · 2026-11-12
> 本文件是核心实体、关联、权限和状态的唯一详细定义。02 定范围，03 定架构；字段或迁移表不一致时按本文件同步纠正，不保留两种实现。全部为接口设计，不是已实现源码。

## 1. 通用约定

- `Id = string`：演示种子用稳定前缀 ID，新增实体用 `crypto.randomUUID()`；不能用数组下标或自增位置做关联。
- `Instant = string`：UTC ISO 8601（例如 `2026-11-12T02:00:00.000Z`）；`LocalDate = YYYY-MM-DD`；显示、周界和截止日期统一按 Asia/Shanghai，不读取宿主机时区决定业务。
- `Base = { id: Id; revision: integer>=1; createdAt: Instant; updatedAt: Instant }`。所有外键同为 Id，字段使用 camelCase；空可选值明确用 `null`，不混用空字符串、0 和缺失。
- `schemaVersion='1.0'`、`seedVersion='1.0'`、`algorithmVersion='1.0'` 独立版本化。金额为人民币元/月，区间包含端点；比率内部为 0–1，展示才乘 100。
- 所有用户输入去首尾空白、Unicode NFC；描述按纯文本渲染，禁止 `v-html` 渲染用户/模型内容。展示名不是关联键。
- 业务函数接收 `Actor={userId,role}` 和 `Clock.now()`，不在算法内部直接调用 `Date.now()`。演示固定时钟为 `2026-11-12T02:00:00.000Z`，演示去向截止为 `2026-11-18T16:00:00.000Z`；与课程验收日期无关。
- 本地四角色是同一浏览器内的教学工作流模拟，不提供抵御设备拥有者或开发者工具的安全隔离；不得使用真实个人数据。

## 2. D1–D7 数据字典

### 2.1 ResumeSections 与快照

```ts
type ResumeSections = {
  basic: { name: string; email: string; majorId: string | null; degree: string | null };
  education: { id: string; school: string; majorId: string; degree: string; startDate: string; endDate: string | null }[];
  experience: { id: string; company: string; title: string; startDate: string; endDate: string | null; description: string }[];
  projects: { id: string; name: string; role: string; startDate: string; endDate: string | null; description: string }[];
  skills: { id: string; skillId: string }[];
  certificates: { id: string; name: string; issuer: string; awardedAt: string }[];
  intent: { cityIds: string[]; expectedSalary: { min: number; max: number } | null };
};
```

`experience/projects/education` 中 endDate=null 表示持续到 Clock 日期，不表示非法日期。数组顺序就是用户排序；id 在版本间稳定。手机号/证件号/政治面貌不收集，虚构联系邮箱亦在企业视图和外发变量中脱敏。ResumeVersion 不含自己的版本历史，避免递归膨胀。`Outcome`、`edu/award/skill`、Application.timeline 均不是新代码允许的别名；旧素材转入种子时按本字典显式映射。

## 3. 持久化、查询与事务

结构化表单验证通过后600ms防抖保存草稿，每次成功保存简历同时追加ResumeVersion并更新versionIds，初次reason=initial、人工修改manual、采纳acceptedSuggestion。保存过程中显示保存中/已保存/冲突；离页刷新可丢未提交的最后600ms输入，需明确未保存提示，不承诺浏览器关闭事件必然写入。AI建议绑定发起时版本；用户保存产生新版本后旧建议失效。采纳后的disposition由本地命令记录，不修改静态回放资产。

- 新项目固定使用 Dexie 封装 IndexedDB，数据库名 `careerpilot-demo`，初始 version(1)。stores 覆盖本文件各实体；contents 合并三类内容；ResumeVersion、ApplicationEvent、AuditLog、CommandReceipt 独立存储；字段表中的唯一/复合索引必须建出。
- `domain` 只做纯函数校验与计算；`services` 组织权限、事务与 Repository。原始 `DataRepository` 不向组件导出，组件不能绕开授权服务查询全库。
- 写命令：`execute(command:{type,commandId,entityId,expectedRevision,payload}, actor, clock)`；type为10迁移/编辑动作的判别字段，payload按type定型。校验 actor 可见范围和版本后，在一个 readwrite 事务中写业务对象、事件、审计、receipt。事件通知只能在提交后触发；事件总线本身不保证原子性。
- 创建命令 expectedRevision=0，已有对象为当前revision，更新成功+1。payloadHash包含命令类型、entityId、expectedRevision与规范化payload；命令类型必须参与哈希，不能把两种业务动作当作相同重试。
- 同 commandId、同 actor、同规范化 payload 重试返回首次结果；同 commandId 不同 payload 返回 `COMMAND_COLLISION`。版本不匹配返回 `REVISION_CONFLICT`，UI 重读后请用户确认，不能盲重试覆盖。
- 事务中禁止等待 AI、HTTP、计时器；Derived 指标在提交后由快照重算，不能先更新图表再提交业务。多标签页通过 BroadcastChannel 通知 revision；不支持多人跨设备同步。
- read/list 接收 Scope：学生仅本人；企业仅自己公司；辅导员仅 counselorId=自己；管理员全量但访问简历须写审计。Scope 的注入在服务端口统一完成，不依赖 UI 传入的 studentId。
- IndexedDB 初始化失败、QuotaExceeded、升级 blocked 必须显示可重试/导出/关闭其他标签页提示，不静默切内存丢数据。schema 升级必须有迁移测试；不得因版本变化自动清空用户数据。

### 3.1 可重建统计的最小审计投影

MetricProjection只保留当前实体中适用的：studentId、companyId、jobId、applicationId、agreementId、counselorId、cohortYear、collegeId、majorId、industryId、active、status、type、source、result、createdAt、scheduledAt、submittedAt、approvedAt、signedAt、terminatedAt。属性未适用时不出现，不保存姓名/联系信息/正文/Blob。Student的scope归属变化及启停、Application/Interview/Agreement/Destination的创建和每次状态变化均记录before/after；初始创建before=null。简历保存/模拟答案提交只记录活动类型和studentId，不保存原文，用于lastActivityAt。

写业务对象、ApplicationEvent、投影日志、sequence计数器与receipt必须同一事务。实体ID取entityId；按(at,sequence)重放至asOf；同固定Clock时刻多命令以sequence决胜，不能依赖随机UUID排序。种子必须提供覆盖统计起点的创建/变更日志；历史无日志的时间段返回不可计算，不用当前状态补历史。最新快照仅是加速；与重放结果须一致。本人清除时删除可关联该生的before/after投影并匿名化剩余动作，历史报表排除已删除主体，隐私清除优先于保留旧总数。该审计是有限统计重建，不宣称完整简历内容事件溯源。

## 4. 招聘与协议迁移矩阵（T5）

`ApplicationStatus = applied | screening | interview | offered | rejected | withdrawn | closed`。原先把协议、去向混入一条“10 态链”的图只保留为业务叙事，不是枚举。终态为 rejected/withdrawn/closed，禁止因“久未推进”更改状态。

| 当前状态 | 事件 / 操作者 | 前置条件 | 新状态 / 同事务副作用 |
|---|---|---|---|
| 无记录 | APPLY / 本人学生 | 职位 published 且 deadline>now；简历至少 basic.name 与教育一条；resumeConsent=true；无相同 [studentId+jobId] | applied；生成脱敏 resumeSnapshot、matchSnapshot、事件 |
| applied | START_SCREEN / 本公司企业 | 岗位归该公司 | screening |
| applied/screening | SCHEDULE_INTERVIEW / 本公司企业 | scheduledAt>now、location 非空、无未取消面试 | interview；创建 Interview(scheduled,pending) |
| interview | COMPLETE_INTERVIEW / 本公司企业 | 关联 scheduled 面试；结果 pass/fail，反馈非空 | pass 保持 interview，fail→rejected；更新 Interview.completed/result |
| interview | CANCEL_INTERVIEW / 本公司企业 | 当前面试未完成，原因非空 | screening；Interview.cancelled；result=pending |
| interview | ISSUE_OFFER / 本公司企业 | 已有 completed/pass 面试，无有效 offer | offered |
| applied/screening/interview | REJECT / 本公司企业 | 原因>=2 字 | rejected；未完成面试 cancelled |
| applied/screening/interview/offered | WITHDRAW / 本人学生 | 没有 signed 协议；原因>=2 字 | withdrawn；取消未完成面试、终止该投递 draft 协议 |
| offered | DECLINE_OFFER / 本人学生 | 无 signed 协议 | closed，closedReason=declined；如有draft协议同时terminated并记录原因/terminatedAt |
| offered | CREATE_AGREEMENT / 本公司企业 | 学生/公司/投递一致；无未终止协议 | offered；创建 Agreement.draft |
| offered | CONFIRM_AGREEMENT / 本人学生或本公司企业 | draft；登记本方确认时间；无该学生其他 signed 协议 | 另一方未确认保持 offered/draft；双确认时 closed(reason=accepted)+signed，写 signedAt |
| closed | TERMINATE_AGREEMENT / 本公司企业 | 对应 signed 协议，明确模拟双方同意标记和>=5 字原因 | application 仍 closed；Agreement.terminated；关联submitted/approved去向撤销为draft，清submittedAt/approvedAt并留审计 |

学生撤回后不能用新 commandId 重投同一职位；UI 可解释“本轮已撤回”，新一轮招聘须另建 Job。管理员不代替业务参与者完成 offer/签约；必要更正通过管理员审计工具说明原因，不提供任意改 status 的输入框。

真实面试的 RESCHEDULE 仅限 scheduled、企业本人、future time；状态仍 scheduled，写事件。幂等规则适用于所有行。协议确认期间若另一个投递抢先签约，第二笔事务失败 `ACTIVE_AGREEMENT_EXISTS`，不能生成双签。

## 5. 去向、帮扶和预约迁移矩阵

| 实体 | 迁移 | 操作者与条件 |
|---|---|---|
| Destination | 无→draft；draft/rejected→draft（编辑） | 本人学生；每生当前一条；unemployed 可保存，但不算落实 |
| Destination | draft/rejected→submitted | 本人学生；类型、组织/行业及必需附件通过校验；internal employment 必须 signed 协议；升学/创业/灵活就业至少一份虚构证明；external employment 需组织名和证明，不强制内部协议 |
| Destination | submitted→approved/rejected | 仅所辖辅导员；拒绝必须>=5 字原因；通过时保存 approvedAt/reviewedBy；审批必须复核关联协议仍有效 |
| Destination | submitted→draft（撤回） | 本人学生；清 submittedAt；旧事件仍在审计 |
| Destination | approved→draft（撤销审核） | 所辖辅导员，原因>=5 字；清 approvedAt；重新计指标；学生不能编辑已批准记录 |
| Assistance | 无→open→reviewed→closed | 所辖辅导员；open 必须 note 与 nextReviewAt；reviewed 必须复查记录；closed 必须确认动作，不代表风险条件自动消失；closed 不再编辑，复发新建 |
| Appointment | pending→confirmed/cancelled；confirmed→completed/cancelled | 学生创建/取消自己的预约；所辖辅导员确认/完成；确认复核无时段冲突；取消保留原因 |
| Job | draft→published→closed；closed→published | 本公司企业；重新发布需新未来 deadline；关闭不取消已有投递/协议，不影响已有历史统计 |

任何未列迁移均返回 `INVALID_TRANSITION`，未授权返回 `FORBIDDEN`，字段错误 `VALIDATION_ERROR`。进入异常预警只产生 `Alert` 派生对象，不新增 EXCEPTION 业务状态；原状态、最后推进时间不被覆盖。

去向字段条件：employment+internal必须application/有效signed agreement、组织名与industry；employment+external必须组织名/industry/至少1附件且applicationId/ agreementId=null；furtherStudy/entrepreneurship/flexible必须source=independent、组织名与至少1附件，内部关联均null，其中创业/灵活就业可填写行业，升学行业为null；unemployed必须independent、不要求组织/行业/附件且不计落实。internal只适用于employment；unemployed允许审批以确认登记，但A7仍归未落实。已提交/已批准不可直接编辑，须依表撤回或撤销审核。

ready→inProgress（START）；inProgress→paused（PAUSE）；paused→inProgress（RESUME）；inProgress→completed（最后一题提交或 END_EARLY）；ready/inProgress/paused→abandoned（ABANDON）。completed/abandoned 不能追加答案。

## 7. 隐私与运维边界

- 企业仅能读自己职位收到、且 resumeConsent=true 的投递快照；公开简历列表为可选 P1，必须 isPublic=true 且脱敏。不得以“企业角色”直接读任意 Resume。
- 本人数据清除需二次确认：事务删除本人User/Student及关联简历/版本、画像、投递/事件/面试/协议、去向/附件、模拟面试/帮扶/通知/预约/问卷记录/评价/反馈/个人AiRun和含本人数据的CommandReceipt；审计删除可反查投影/输入并将actor/entity关联改为不可反查标记；取消任务/清运行缓存/退出当前会话、统计重算。不会清除其他学生、公司职位或无关记录。若保留匿名删除审计，只含动作与时间，不保留旧ID映射。重新体验用管理员reset重建虚构账号。
- reset-demo 是管理员/演示入口的危险操作：取消所有 AI 任务、递增运行 epoch、一个事务清空业务 stores 并导入经校验 SeedPack、恢复固定时钟和 REPLAY、清偏好/缓存、退出到 P01；失败整笔回滚，不留下半套种子。交付包语料不被删除。
- 复位的Clock/运行模式作为Config与种子同事务提交，成功后才切UI会话/清浏览器偏好。事务失败保留旧业务、Clock与模式并提示重试；已取消任务不复活，epoch保持递增以拒收旧回包。“失败回滚”不是恢复已经发出的外部请求。
- 角色只能由管理员授予；不提供公开注册入口。演示入口允许选择预置角色但必须显眼说明“教学角色模拟”。禁止禁用/降级最后一个管理员；角色变化使关联会话失效。
- 角色变更必须满足User/Student/Company的一对一绑定；若目标角色缺必需关联，返回VALIDATION_ERROR而非制造悬空账号。已有学生/公司业务时不得直接变更其角色，需先清除/迁移关联并留审计；辅导员有在辖学生时禁用/改角色须同事务先转交给另一active辅导员，未指定转交则拒绝。初始管理员不能用演示切换绕过上述写权限。
- Attachment 的文件名也不外发；本地 Blob 可持久化但不是外部上传服务，不提供跨设备下载 URL。容量失败不丢表单草稿。

## 8. 种子包与固定验收样本

完整包固定下限：40 学生及对应学生用户、8 企业及对应企业用户、4 辅导员、1 管理员、100 岗位、120 投递、40 真实面试、8 模拟面试、40 简历、12 signed 协议、25 去向、12 教学内容、至少 24 面试题；Dictionary的college/major/industry/city/jobCategory/degree六种kind均非空。学生覆盖 4 专业、岗位覆盖 6 行业和 8 技能族。数据全部重新虚构，不复制原库个人字段。

种子治理口径锚点：20 approved 去向（employment 12、furtherStudy 5、entrepreneurship 2、flexible 1），5 submitted，15 无去向记录；落实率=20/40=50%。120 投递中 40 曾安排真实面试、20 曾获 offer、12 signed；40 面试为 pass20/fail10/pending10；平均投递=3.0、已完成面试通过率=20/30≈66.7%。所有事件时间<=固定时钟。额外实体不得改变上述锚点，增加种子规模须升级 seedVersion 和预期值。

上述锚点针对管理员/完整本届scope，不要求每个辅导员子集也等于50%/3.0/66.7%。SeedPack须另含按counselorId/majorId的预期聚合表，合并后回到全量；P15默认遵守当前角色scope，演示切管理员展示全局锚点时须说明，不得为显示40学生绕过辅导员权限。

独立单测小样本使用 4 学生：已批准就业、已批准升学、已提交创业、无记录各一人；落实率 50%，已落实/推进中/未登记=2/1/1。小样本不能混进完整种子包参与统计。

种子必须通过外键、唯一键、状态事件可重放、没有未来事件、附件实际 Blob 可读、角色作用域和固定锚点断言。详细测试编号见 13，落地任务见 14。

## 10. 网关配置隔离（v1.5）
