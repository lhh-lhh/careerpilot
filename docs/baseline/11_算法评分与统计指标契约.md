# 11 · 算法评分与统计指标契约

> 路鸣职引 CareerPilot · v1.5 · 2026-11-12
> 适用于 `src/domain/` 的纯函数、Worker 与测试。阈值为教学演示的透明启发式，不是经过行业验证的招聘测评；严禁宣传为录用概率、真实能力认证或因果预测。参数修改须升级 algorithmVersion，不能为追求演示分数临时调参。

## 1. 全局规则

所有函数不依赖 Vue、网络、数据库或系统时钟。入口接收完整快照、已注入的 now 和配置；返回值含 algorithmVersion、输入 revision 与计算依据。缺失值按各维明确的中性值/0值计算并返回missingData，不能把“不知道”展示成已证实不匹配；空分母返回 null，UI 显示“暂无可计算数据”。真实零值显示 0。对学生权限范围先过滤，再计算指标。

实现位置：`domain/matching`=T1、`domain/resume`=T6、`domain/interview`=T4、`domain/metrics`=A7、`domain/retrieval`=T2。关键词/同义词/题库是版本化数据，不散落组件。

## 2. T1 可解释匹配（MVP）

### 2.1 标准化与六维分数

固定维度顺序 `skill,major,degree,city,salary,experience`，默认权重 `[0.35,0.20,0.10,0.15,0.10,0.10]`。用户权重必须为有限非负数，先除以总和；全零回到默认并提示，负值/NaN/Infinity 返回 VALIDATION_ERROR，不写偏好。

技能名先 NFC、小写、去首尾空白，再用 SkillOntology 的明确别名转 skillId（如 js→JavaScript）；不做未经登记的相似词猜测。每个要求技能只算一次：同 ID=1，候选人拥有其后代技能=0.5，其他=0；多个命中取最大，不累加。不从父技能反推已掌握子技能。未登记词保留为 unknown 标签但不误匹配。

| 维度 | 计算规则（输出 0–1） | 无条件/缺失规则 |
|---|---|---|
| skill | `sum(requirement.weight * bestHit) / sum(requirement.weight)` | JD 无技能要求为 1；JD 有要求、简历无技能为 0 |
| major | majorId 在 preferredMajorIds 中为 1；与任一要求同 Dictionary.parentId 为 0.7；明确不同学科组为 0.3 | JD 不限为 1；简历 majorId 未填为 0.5，并给 missingData |
| degree | 等级 `secondary=1,associate=2,bachelor=3,master=4,doctor=5`；达到或超过=1，差一级=0.5，差两级及以上=0 | JD 不限为 1；简历未填为 0.5；不按学校名或院校层次加减分 |
| city | Job.cityId 在 intent.cityIds 中为 1，否则为 0 | 学生没有城市偏好为 1（不限），不推断籍贯 |
| salary | 两区间有交集=1；无交集时 `max(0,1-gap/expected.min)`；gap 为两区间距离 | JD 面议或学生未填为 0.5，标注不可判断；expected.min 必须>0 |
| experience | `min(1, months / minExperienceMonths)`，months 为有效 experience 时间区间并集的整月数 | 岗位要求 0 月为 1；没有经历为 0；项目不能自动算实习 |

所有金额/权重必须有限数，Job薪资min>=0、max>=min；期望薪资min>0、max>=min。majorId的学科父节点仅两边均非null且同ID才给0.7，两个空parentId不算同学科。匹配缺失标记与分值并存；不得把缺失标签隐藏成事实不符。

experience 以日历月编号 `year*12+month` 计算 end-start，同月为 0；重叠区间合并后求和，end=null 取注入 now 所在月，不算未来月份；开始晚于结束拒绝保存。日期缺失记录不计月且显示提示。

### 2.2 总分、解释与 What-if

`rawTotal=100*Σ(normalizedWeight*dimensionScore)`。每维 contribution 同乘 100，范围为 0–100 的分数点；排序使用未取整 rawTotal，持平按 jobId 字典序。显示一位小数；六维显示贡献先四舍五入，再将与显示 total 的差额加到最大贡献维度（同值按固定维度顺序），使显示可加总。

MatchExplanation={jobId,rawTotal,total,dimensions:[{key,score,weight,contribution,hits:Id[],misses:Id[],missingData:boolean}],missingSkills:[{skillId,gain,costDays}],algorithmVersion,inputRevision}。total 是显示值，rawTotal保留未舍入值供排序；hits/misses 指真实要求，不以生成文本作为计算依据。

What-if 在拷贝快照上追加假设技能或修改权重，返回 before/after/delta/rankBefore/rankAfter；不能修改真实简历、历史投递快照。gain 由同一 match 函数重算差值；costDays 从本体读取且>=1，按 gain/costDays 降序，再 skillId 排序。假设技能必须标“尚未证实”，不得一键写进简历当事实。只有用户显式编辑并确认自己的事实才能改变真实技能。

### 2.3 固定测试向量与复杂度

六维全为 1→100；仅 city=0，其余为1→85；六维均0→0。JD 要求 Vue、权重1，简历技能 Vue→skill=1；简历仅其子技能 Pinia（本体声明 Pinia.parentIds=[Vue]）→0.5；仅父技能“前端”→0。全零权重必须恢复默认。已知经历 2025-01..2025-04 和 2025-03..2025-06 的并集为5个月，不是6个月。

本体 DAG 祖先集合预处理上界 `O(K*(K+E))`、内存 `O(K²)`；MVP K<=256，E<=512。预处理后技能 ID 查询均摊 O(1)，单岗位匹配 `O(m*r)`（m 简历技能数、r 岗位要求数），n 岗排序 `O(n*m*r+n log n)`。Worker 不改变复杂度，负责避免阻塞主线程；MVP 单 Worker，按每20岗位分批检查取消，不为了“并行”创建无界线程。性能计时包含序列化/Worker 消息往返，不只计内核。

## 3. T6 简历体检与双轨对照（MVP）

### 3.1 完成度

六维权重保持原方案：basic15、education15、experience25、projects20、skills15、certificates10。每维是该维四项检查通过数量/4*100；总分是加权和，不额外叠加 AI 分或 ATS 分。无经历、证书是“内容未提供”，不表示能力低劣，界面说明这是简历信息完整度。

| 维度 | 四项检查（每项等权） |
|---|---|
| basic | name非空；email格式有效；majorId存在；degree是合法等级 |
| education | 至少一条；每条school/majorId非空；每条日期合法；每条degree合法 |
| experience | 至少一条；每条company/title非空；每条日期合法；每条description>=20字 |
| projects | 至少一条；每条name/role非空；每条日期合法；每条description>=20字 |
| skills | 至少一条；规范化去重后>=3技能；所有skillId可解析；无重复技能 |
| certificates | 至少一条；每条name/issuer非空；每条awardedAt合法且<=now；没有同name+issuer+awardedAt重复 |

没有任何条目时，该维四项全部失败，不允许空数组“每项均满足”得75分。完整样本六维100→总分100；只有经历维度0且其他100→75。

### 3.2 问题检测与 ATS

STAR 检查仅做文本线索：S=`项目/期间/场景/背景`；T=`目标/任务/负责/需要`；A=`实现/开发/设计/优化/组织/分析/完成`；R=`提升/降低/减少/增长/完成/交付/结果`。每类至少命中一词才标存在；必须返回原句位置。数字线索正则 `\d+(?:\.\d+)?\s*(?:%|个|人|次|天|周|月|秒|毫秒|元)`，只有年份、学号不能算成果证据。只是线索，不声称理解事实真伪。

ATS=`命中的规范化JD技能个数/去重JD技能个数`，只算精确命中，区别于 T1 的层级半分；JD 空或未选 targetJob 返回 null，UI 显示“不适用”。时间空档是已排序的经历/教育结束到下一开始>6个日历月，提示核实，不扣完成度；两段>=20字描述规范化后完全相同为冗余提示。

双轨消融改为：原文、RULE 建议后预览、AI/人工审校回放建议后预览，三者均用**同一规则评分函数**重算。名称为“原文规则分/规则改写后规则分/生成建议后规则分”，禁止称模型评分或融合分；展示不保证分数一定提升，事实不变的措辞改善可能分数不变。

### 3.3 建议采纳

建议必须绑定 resumeVersionId、fieldPath、before 原文和 evidence[]。采纳前比对当前字段和 before，冲突返回 STALE_SUGGESTION；采纳生成新 ResumeVersion 并重算，驳回仅记录 disposition，不改简历。after 中新增数字、公司、岗位头衔或项目名必须能逐项指向用户提供证据；无证据只能用 `[请填写经核实的成果]`，有占位符时禁止直接采纳，先人工填写。

不把“负责”无依据升级为“主导”；RULE 可做结构化重排与提示，不新编事实。`keepMyTone=true` 保留原动作词；false 可换不改变职责程度的同义表达；strategy=`structure/evidencePrompt/concise`，由用户点击换版按序循环，纳入回放指纹，不用不可复现随机种子。

## 4. T4 面试选题、追问与评分（MVP）

默认3道主问题，行为/专业/HR各1题；按技能与 rubric 未覆盖数量的加权增益贪心选题，类型满足为硬条件，持平按题库 ID；不足时显示“题库覆盖有限”并选本类型首个未使用题，不编造覆盖。MVP的questionId/技能/关键词由版本化题库决定，LIVE仅可改写题目措辞，不能临时创建另一套评分题；RULE 始终可用。每题最多2次追问；优先级：未命中题目关键词→“请结合问题说明”；有T/A但无R→问结果；其余缺数字线索→询问可核实成果；之后推进。

答案规范化后、合并本题所有追问，用以下规则评分；完整文本仅作为本地证据，AI 不改数值。

| 维度 / 权重 | 规则 |
|---|---|
| relevance / .25 | `min(1,命中的question.keywords数/max(1,keywords数))*100`；题库至少1关键词 |
| star / .20 | 11 §3.2 的四类 STAR 线索命中数/4*100 |
| evidence / .15 | 独立量化成果线索去重后0/1/>=2条→0/50/100 |
| skill / .20 | 答案命中本题skillIds的规范名/别名比例*100；本题无技能标签时取relevance，不给无条件满分 |
| structure / .10 | 按 `。！？；\n` 切非空句，2–8句给50分；另有`首先/其次/然后/最后/因此`任一给50分；最多100 |
| consistency / .10 | 是否出现版本化词典中的显式互斥线索：无命中100，一组50，两组以上0；MVP互斥对为“独立完成/未参与”“没有使用/熟练使用”；仅在两词处于同一句且作用于同一skill关键词时计数，除此显示“未检测到表面冲突”，不宣称逻辑真实 |

空白答案不给默认100一致性，总分和各维均0；不提交空白，用户可显式跳过并记录0分。本题总分为六维加权；报告各维为已答/跳过题均值，overall 由报告维度再加权，保留1位小数。未作答题不计均值但显示 completion=已提交主题数/计划题数。growthDelta 只对同岗位、同rubricVersion、同题本的上一场 completed 会话比较；否则 null 并说明不可比较。分数不用于真实候选人排名。

每个非零 relevance/star/evidence/skill/structure 项必须有答案原文的 start/end 与 quote；consistency 保留检查结果和冲突片段，无冲突不能伪造证据。证据切片越界视为守卫失败。

## 5. A7 指标口径与预警（MVP）

### 5.1 范围与时间

查询 `MetricQuery={cohortYear,collegeId?,majorId?,from?,to?,asOf}`；角色 scope 为硬过滤，与查询条件取交集。asOf 来自 Clock；累计状态统计含at<=asOf，窗口事件数采用 `[from,to)`，to<=asOf。from/to只影响当期新事件与趋势，不悄悄改变累计漏斗/落实率的含义。周从上海时间周一00:00起，最近8周。状态取10 §3.1按(at,sequence)重放至asOf的最末投影，不能读未来状态充作历史；无历史覆盖显示不可计算。

| 指标 ID | 定义 | 零分母与注意事项 |
|---|---|---|
| destinationRate | 分子：scope内当前 Destination.approved 且 type!=unemployed 的去重学生；分母：scope内 active 的本届学生 | 无学生→null；submitted/rejected不能算落实 |
| destinationStructure | 同口径按 employment/furtherStudy/entrepreneurship/flexible 分类计数；另列 pending（submitted）、unregistered（无记录/draft/rejected/unemployed） | 各生只能落一档，合计等于分母；图上中文为已落实/推进中/未落实，不能把全部未落实称“未登记” |
| applicationFunnel | 创建投递数、曾有有效 SCHEDULE_INTERVIEW 事件的投递数、曾有 ISSUE_OFFER 的投递数、签署过且截至asOf仍有效协议的投递数 | 按 applicationId 去重，含历史达成阶段而非仅按当前status计；撤回不抹掉曾面试；排除 MockSession |
| avgApplications | scope内截至asOf投递数 / active学生数 | 无学生null；展示1位小数 |
| interviewPassRate | completed/pass真实面试数 / completed(pass+fail)真实面试数 | pending/cancelled不进分母；无completed→null |
| majorIndustry | approved employment 去向按 student.majorId × destination.industryId 去重学生计数 | 升学等不伪造行业；缺industry的就业去向拒绝批准 |
| weeklyDestinationTrend | 每周末前有效approved且非unemployed学生数/该scope学生数；同时展示当周新批准数 | 周末超过asOf时按asOf截断；撤销审核后趋势按事件回放计算 |
| activeSeekers | 近14个24小时内曾投递/参加真实面试/提交模拟练习的去重学生，且当前无approved已落实去向 | MockSession只影响活跃度，不影响漏斗或通过率 |

自然语言问数只允许 `destinationRate/byMajor/funnel/alerts/avgApplications/interviewPassRate` 六种 intent。规则按包含词映射：“哪个专业…最低”→byMajor升序，“落实率”→destinationRate，“漏斗/转化”→funnel，“预警/风险”→alerts，“平均投递”→avgApplications，“面试通过”→interviewPassRate；从更具体模板到一般模板；多意图/无匹配澄清，不执行任意代码/SQL，不越出scope。生成文字的数值以指标 ID 占位引用本地结果，不能接受模型自报数。

### 5.2 预警配置

只对尚未approved落实的active学生计算；以下按固定时钟评估，不写Application.status：

| ruleId | 触发条件 | 风险分 |
|---|---|---:|
| inactive7d | 距max(enrolledAt,最后一次真实招聘推进/简历保存/模拟答案提交时间)>=7个24小时 | 30 |
| applicationsWithoutInterview | 投递>=5 且从未有有效面试安排 | 25 |
| resumeIncomplete | 简历完成度<60（缺简历为0） | 20 |
| deadlineApproaching | 0<=截止-now<=7个24小时，且无approved落实去向 | 25 |

总分0不入名单，1–29低、30–59中、60–100高；按分降序再studentId。返回所有触发ruleId、原始计数、阈值、lastActivityAt、asOf和建议动作。钟表超过截止时另显示“已过截止”待办，不把负天数当临近；不私自新增风险权重。帮扶状态与预警解耦，关闭帮扶不清除规则，复查重新评估。生成建议仅在辅导员确认后写入 Assistance。

### 5.3 固定样本

10 §8 小样本：落实率=50%，去向三档=2/1/1。没有面试数据时通过率=null，不是0%。一个学生5投递、0面试、完成度50、8天无活动、距截止6天→100高风险，四原因齐全；批准落实后不再列该生。完整种子固定锚点以10 §8为准，图表、问数、导出必须一致。

## 6. T2 本地检索（P1，不是 MVP 放行条件）

启用A5时执行：按标题/自然段切分，最长400字符、重叠40；NFC与英文小写，中文相邻二元切分+领域词典最长匹配，英文数字按词切；停用词表版本化。BM25使用 `k1=1.2,b=.75,idf=ln(1+(N-df+.5)/(df+.5))`。Top3，持平按chunkId。

confidence=`.7*queryTokenCoverage+.3*min(1,topScore/8)`；无命中/coverage<.4/confidence<.55均拒答。queryTokenCoverage=问题去重非停用token在Top3合并文本中的覆盖比例。引用只允许索引中真实chunkId，excerpt必须是原文切片；RULE仅摘录原文，不伪装生成。10条库内标注问题Recall@3>=.8，另5条库外拒答率>=.8；样本与阈值固定后不能按测试答案调词典。未启用A5时报告不得宣称六核全部完成。

## 7. 消融与性能验收边界

T1 至少10个固定简历×职位场景，由人工标注相关/不相关；对比纯关键词精确覆盖基线、加入本体、加入六维，记录Top5、Precision@5、排序变化及失败例，不预承诺提升。样本仅是教学验证，不能外推真实就业效果。T6 使用相同评分器对照，禁止引入第二个不透明评分源。

性能参考为验收电脑Chrome/Edge、生产构建、100岗位×1简历；先预热5次，连续30次，记录硬件、浏览器、schema/seed/algorithm版本；匹配往返p95<300ms，普通筛选/路由p95<200ms，首屏p95<1.5s。首次打开断外网、缓存清空后仍须能加载本地所有资源；只断业务外网，不停本地静态服务。初次本体预处理耗时单列，不藏进“预热”省略。

真实AI接入不改变本册algorithmVersion=1.0及固定数值口径；LIVE只增强文本，其网络延迟/成功率单列，不混入本地性能阈值。REPLAY/RULE确定性，LIVE结果不承诺字面完全一致或8秒内必定成功；超时依12/15回退。
