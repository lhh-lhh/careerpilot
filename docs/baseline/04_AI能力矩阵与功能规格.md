# 04 · AI 能力矩阵与功能规格

> 项目：路鸣职引 CareerPilot　版本：v1.5 · 2026-11-12
> 上游：`02` SRS、`03` HLD　下游：`05` 界面规范
> 本文件回答：AI 到底落在哪些功能上、每个功能怎么算、断网怎么办、凭什么算"技术难度"。

---

## 1. 设计立场（三条判定原则）

用户设想"接入 AI 来奠定总的项目设计，功能分布在多个模块"。据此确立三条原则，用于否决跑偏的方案：

1. **AI 是能力层，不是页面**。不做一个大聊天框再挂菜单；每个 AI 能力必须嵌入具体业务页面（简历页里改简历、岗位页里解释推荐、驾驶舱里预警）。A10 统一入口只是"能力编排的捷径"，不是主界面。
2. **分数与数值绝不由大模型直接给出**。所有评分、匹配度、指标、预警阈值均由本地确定性内核计算；大模型只负责**生成文本、归类意图、解释已有数值**。理由：可复现、可测、可答辩、不会出现"同一份简历两次分数不同"。这也是本项目与"套壳 AI"最关键的分界。
3. **每个 AI 功能都必须有 RULE 态替身**。任何一个模块若离开网络就白屏，整个 8 分钟演示就押在了第三方服务上。因此 A1–A10 全部定义本地降级实现。

> 这三条直接回应了本项目设定的“机制深度、隐私、保真表达”三项质量目标（见 `02 §1.2`），也把"技术难度"从"调了几个 API"转成"设计了几个可讲原理的机制"。

## 3. 逐模块功能规格

> 每个模块统一按「价值 → 输入 / 输出 → AI 做什么 / 自研内核做什么 → 降级 → 界面 → 验收证据」描述。下列输出是页面ViewModel概览，不是Provider payload：数值由11计算，Provider只返回12的文本增强结构，Schema见contracts/ai-contracts.schema.json。可选模块启用前另补详细契约。

### A1 · AI 简历诊断与完善（MVP）

**价值**：把"简历不知道差在哪"变成一份可逐条采纳的体检单；提供可解释诊断与同规则重评，不宣称已完成竞品实测。

| 项 | 规格 |
|---|---|
| 输入 | `Resume`（含教育/经历/项目/技能/证书 5 段）、可选 `targetJob`、用户开关 `keepMyTone` |
| 输出 | `{ score, dimensions[6], issues[], atsCoverage, versions[], traceId, mode }`；`issues[i] = { id, severity, field, evidence, reason, before, after, source: 'rule'\|'ai', accepted }` |
| 自研内核（T6） | ① 完成度评分 6 维加权（基础信息 15 / 教育 15 / 经历 25 / 项目 20 / 技能 15 / 证书 10）；② STAR 结构检测（动作动词、量化数字、结果词、职责描述长度）；③ ATS = 规范化精确命中JD技能数 / 去重JD技能数，空JD为null，并列缺失标签；④ 时间空档与冗余检测；⑤ **双轨消融**：原文、规则建议稿、生成建议稿分别用同一规则评分器重评，比较可解释差异；不定义AI分或融合分 |
| AI 负责 | 仅做「逐条改写建议 + 理由文本 + 明确strategy与保留语气开关」；不产生分数；输出强制含 `before/after`，禁止编造经历 |
| 降级 | RULE：本地保真改写模板 + 结构重排 + 待用户补充占位提示（有占位不可直接采纳），仍可生成 diff；REPLAY：准备2组典型简历的文本增强语料（RULE/CURATED来源如实标记），当前分数仍本地重算 |
| 界面 | P04 三栏：左段落导航、中编辑器（原文 ↔ 改写 diff 卡）、右诊断抽屉（体检环、6 维条、问题清单、ATS 覆盖率、版本对比） |
| 验收证据 | 体检分雷达；一条"采纳改写"的前后对比；三稿同规则重评表；ATS 覆盖率提升数值；"保留我的表达"开关导致两种不同改写 |

**反同质化设计（对应 NFR-08）**：用户显式选择strategy（structure / evidencePrompt / concise）及keepMyTone；REPLAY/RULE完全相同输入不随机换词；LIVE相同输入可能波动，不承诺确定性，并在UI按12标明真实来源与请核实；所有建议可驳回，原文永不自动覆盖。

### A2 · AI 模拟面试（MVP）

**价值**：解决"没有低成本练习机会"；对标各校"AI 模拟面试舱"，但用可解释评分替代黑盒评价。

| 项 | 规格 |
|---|---|
| 输入 | `job`、`resume`、轮次类型（行为面 / 专业面 / HR 面）、难度、历史 `MockSession[]` |
| 输出 | `{ sessionId, questions[], answers[], followUps[], scores{ dimension, value, evidence[] }, overall, growthDelta, traceId, mode }` |
| 自研内核（T4） | ① **题本覆盖矩阵**：岗位技能标签 × rubric 维度 → 按11固定选择behavior/technical/hr各1题，稳定排序且不重复，覆盖不足明确提示；② **追问状态机**：解析答案中 STAR 要素，缺结果→追问"最终成果如何量化"，含模糊词→请澄清真实依据，不诱导编造数字，答非所问→复述题目；最多 2 次追问后推进；③ **rubric 评分** 6 维（内容相关性 / STAR 完整度 / 量化证据 / 岗位技能命中 / 表达结构 / 逻辑一致性），按11固定权重（变更须升级rubricVersion），命中证据摘录原文片段 |
| AI 负责 | 在本地既定题本与技能覆盖内措辞题目/追问、写定性评语；不让生成题目绕过固定题本；**评分数值由 rubric 算**，AI 评语只作补充，且必须引用 `evidence[]` |
| 降级 | RULE：本地题库（按岗位类别） + 关键词/正则评分；REPLAY：准备3主题完整面试的文本增强语料（含追问/反馈；评分本地计算），逐字流式回放 |
| 界面 | P05 面试间：左侧对话气泡、右侧实时评分环与轮次进度、底部输入区（文字必做，Web Speech 语音为可选加分）；P05b 报告：6 维雷达、逐题证据高亮、历史成长曲线、导出按钮 |
| 验收证据 | 一次完整的"提问 → 作答 → 自动追问 → 下一题"录屏；评分展开能看到命中的原句；同岗位、题本和rubric的可比成长曲线；断网切 RULE 仍可完成一轮 |

### A3 · 可解释人岗匹配（MVP · 头号招牌）

**价值**：把"岗位推荐"从黑盒列表变成可诊断、可干预的过程；按本项目技能DAG与透明规则解释每项推荐，不依赖未核实政策引文。

| 项 | 规格 |
|---|---|
| 输入 | `Resume`（技能/专业/学历/城市偏好/薪资期望/经历）、`Job[]`、`Weights`（6 维权重，用户可调） |
| 输出 | `{ jobId, total, dimensions[{ key, score, weight, contribution, hits[], misses[] }], missingSkills[{ skill, gain, cost }], whatIf[], explanationText, rank, mode, traceId }` |
| 自研内核（T1） | ① **技能本体归一**：别名表（`JS→JavaScript`、`Py→Python`）+ 层级父子关系（前端 → Vue → Pinia），解决词面不同导致的漏匹配；② 六维打分：技能覆盖 / 专业 / 学历 / 城市 / 薪资 / 经验，各维归一 `[0,1]`；③ `total = 100·Σ wᵢ·sᵢ`，同时输出每维 `contribution = 100·wᵢ·sᵢ` 与命中的具体技能；④ 差距解释：`missingSkills` 按「边际提升 ÷ 补齐成本」排序；⑤ **What-if 反事实**：调权重或假设新增技能后重算全库，返回 Δscore 与排名变化，形成"若补齐 X，Y 岗位可从 72 → 85"的解释；⑥ 单Web Worker分批计算与取消；不改变渐近复杂度 |
| 复杂度 | DAG预处理O(K(K+E))、内存O(K²)；单岗位O(m·r)、全库含排序O(n·m·r+n log n)。详细符号、缺失值、权重/排序/舍入与计时统一见11 §2/§7 |
| AI 负责 | 把结构化解释转成自然语言推荐语与补齐建议；**不参与打分** |
| 降级 | RULE：T1 本身就是确定性内核，**断网时功能完整可用**（这是 A3 最大的演示优势）；REPLAY：录制自然语言解释文本 |
| 界面 | P06 三栏：左筛选器、中岗位卡列表（总分环 + Top3 命中标签）、右解释抽屉（6 维贡献条、雷达、缺失技能清单、What-if 权重滑杆与假设技能开关、一键投递） |
| 验收证据 | 贡献分解逐层展开到"命中了哪个技能"；拖动权重滑杆列表即时重排；反事实解释前后分数对比；算法 vs 纯关键词基线的 Top5 消融表；伪代码 + 复杂度分析页 |

> **为什么这是最强的技术难度证据**：它同时具备自研算法、可解释性、交互实验（What-if）、性能工程（Worker）和可量化评测（消融）——报告"关键技术"一节可以完整讲 2 分钟，而不是一句"接入了大模型"。

### A4 · 生涯数字画像与成长路径（P1）

| 项 | 规格 |
|---|---|
| 输入 / 输出 | 简历 + 成绩 + 投递 + 面试评分 + 目标岗位 → `{ profileVector[8], gaps[], actions[{ type, title, reason, costDays, expectedGain }], narrative }` |
| 内核 | 能力向量归一（8 维：专业技术 / 工程实践 / 项目协作 / 表达沟通 / 行业认知 / 数据能力 / 证书资质 / 求职活跃度）；与目标岗位画像求差；提升动作按 `expectedGain / costDays` 排序 |
| AI | 生成个性化解释与"本学期可做的三件事"文案，动作本身由规则排序 |
| 降级 | RULE：纯规则画像 + 模板文案 |
| 界面 / 证据 | P08 雷达 + 差距条 + 路径时间轴；证据：画像随一次模拟面试评分自动更新 |

### A5 · 政策与规则智能问答（P1 · 本地 RAG）

| 项 | 规格 |
|---|---|
| 输入 / 输出 | 自然语言问题 + 本地知识块 → `{ answer, citations[{ chunkId, title, excerpt, score }], confidence, refused, traceId }` |
| 内核（T2） | 知识块切分（政策/规则/指导文章按段 + 标题路径）→ 中文二元切分 + 领域词典 → **BM25** 打分 → Top-K → 置信度（首末分差 + 覆盖率）→ **低于阈值直接拒答**，返回"未找到依据段落" |
| AI | 只能基于传入的检索段落生成答案，强制带 `chunkId` 引用；无段落不生成 |
| 降级 | RULE：直接返回 Top-3 原文段落作为答案（不生成），**完全离线可用** |
| 界面 / 证据 | P09 问答 + 右侧引用卡（点击跳转到原文高亮）；证据：引用溯源截图、故意问库外问题触发拒答、10 条人工标注问题的召回率小表 |

### A6 · 智能 JD 生成与候选人摘要（P2）

| 项 | 规格 |
|---|---|
| 输入 / 输出 | 岗位要点（名称/类别/城市/薪资/3–5 个关键词；手工发布始终必做）→ 结构化 `{ responsibilities[], requirements[], skillTags[], tone }`；候选人 → `{ matchSummary, strengths[], gaps[] }`（复用 A3 解释） |
| 内核 | 技能标签抽取与字典对齐、必填字段一致性校验、摘要模板槽位 |
| 降级 | RULE：行业 JD 模板 + 标签填充 |
| 界面 / 证据 | P13 企业台"AI 起草"抽屉；证据：生成 → 人工编辑 → 发布后出现在学生端 |

### A7 · 就业质量驾驶舱与慢就业预警（MVP · 治理端招牌）

| 项 | 规格 |
|---|---|
| 输入 / 输出 | 权限scope内投递 / 真实面试 / 去向 / 简历快照 → `{ metrics{}, charts[4], alerts[{ studentId, level, reasons[], suggestedAction }], nlQueryResult }` |
| 内核 | ① **指标口径唯一真相源**：去向落实率、投递转化漏斗、专业 × 行业热力、周趋势、平均投递数、面试通过率；② **预警规则**：连续 N 天无进展 / 投递数超阈值且面试为 0 / 简历完成度低于阈值 / 临近截止未登记去向 → 按加权风险分排序并给出全部触发原因；③ **自然语言问数**：仅11六类白名单意图把问题映射到带scope/asOf的指标查询（如"哪个专业去向落实率最低"→ `metrics.byMajor`），**数值由本地聚合函数算，模型只组织语言** |
| AI | 生成归因文字与帮扶建议；不产生任何数值 |
| 降级 | RULE：指标与预警完全本地计算，文案用模板；**断网可用** |
| 界面 / 证据 | P15 四图 + 预警名单 + 问数输入框 + 帮扶闭环记录；证据：图表可下钻、预警点开能看触发原因、问数结果与图表数值一致 |

> 与竞品的差异：多数高校平台把"驾驶舱"做成静态报表，本项目把它做成**预警 → 建议 → 帮扶记录 → 复查**的闭环，并把原项目散在 8 张表里的数据真正用起来（修复 P1-2）。

### A8 · 协议 / 去向材料合规检查（P2）

AI提示语为P2；10规定的必填/一致性/状态校验始终必做。输入表单 → `{ completeness, inconsistencies[], statusLegal, hints[] }`；内核做必填校验、字段一致性（企业名称在协议与去向中一致）、状态合法性（协议仅 `draft/signed/terminated`，**显式修复 P0-5**）；AI 只写提示语；RULE 态完全可用；界面 P11；证据：故意填错触发拦截并不写入库。

### A9 · 问卷与反馈智能归纳（P2）

开放文本 → `{ themes[{ label, count, samples[] }], sentiment, quotes[] }`；内核用领域关键词与情感词典做主题归类，AI 写摘要且必须附原句引用；RULE 态返回词频主题；界面 P15 子面板；证据：归纳结果可点开查看原句。

### A10 · 统一智能入口（P1）

全局命令面板 / 首页侧栏；**意图分类器**（规则 + 少量示例）把用户请求路由到 A1–A9 的一个或多个动作，支持两步编排（例："帮我看看能不能投这个岗" → A1 体检 → A3 匹配与建议），结果以**业务卡片**呈现而非长文本；明确不做通用闲聊（对应 `BL-07` 裁剪原则）；RULE 态按关键词路由；界面 P03 / 全局；证据：一次多步编排录屏。

## 4. AI 工程层（所有模块共用）

### 4.1 统一调用链（8 步，T3）

```
① 组装变量（从作用域services取得不可变业务快照与domainRevision）
② 脱敏中间件（手机号/证件/真实姓名 → 占位符；写 masked=true）
③ Prompt 版本选取（module + promptVersion，模板与代码分离）
④ Provider 选择（LIVE / REPLAY / RULE）+ 超时 8s + Token 预算
⑤ 发起请求（SSE 流式 / 非流式）
⑥ 完整输出Schema与语义双校验；失败丢弃预览，不自动重试可能计费的请求
⑦ 非取消失败 → 降级链 LIVE → REPLAY → RULE，记录 fallbackReason
⑧ 写 AiRun 审计（module / mode / promptVersion / traceId / usage / masked / 降级原因），返回结果给 UI
```

### 4.2 关键契约

| 项 | 约定 |
|---|---|
| 输出格式 | 所有模块定义 `schema`（JSON Schema）；UI 只消费校验后的对象，杜绝"模型返回一段 Markdown 直接塞进页面" |
| Prompt 管理 | `prompts/{module}.v{n}.ts`，含系统指令、输出 schema 描述、反幻觉条款（"只能基于给定数据，不得编造经历/数字，不确定则留空"） |
| 录制回放 | 严格按12的三版本+domainRevision+规范化inputHash精确匹配；origin与reviewer可追溯；Unicode安全分块<=3秒 |
| 超时与取消 | `AbortController`；页面切换/角色切换/用户停止/reset立即取消且不fallback；并发2、等待队列4；epoch及旧版本回包丢弃 |
| 角标与透明 | 按12显示“模型生成/LIVE”“示例回放/REPLAY及来源”“本地规则/RULE”，共同标请核实/可驳回；不能把RULE/CURATED说成模型调用 |
| Token 预算 | 单次请求上限、单次会话累计上限，超出自动切 RULE 并提示 |

### 4.3 为什么"三态"比"直接调 API"更有技术含量

它把不确定性当成一等公民来设计：Provider 抽象、降级链、结构化输出守卫、脱敏与审计、可回放的确定性演示——这些都是可在报告里画架构图、写状态转移、给出失败率数据的**系统机制**，而不是"调用了一个接口"。同时也正好覆盖课程大纲第 5、6 章（HTTP/SSE/状态码、异步取消与并发编排）。
