# 12 · AI 输出与回放协议契约

> 路鸣职引 CareerPilot · v1.5 · 2026-11-12
> 本文冻结 MVP A1/A2/A3/A7 的三态契约，配套 `contracts/ai-contracts.schema.json`（JSON Schema 2020-12）。它是文档契约资产，不是应用代码。扩展模块启用前须追加独立 payload schema，不能直接复用自由 JSON。

## 1. 本地领域结果与生成文本分开

`10/11` 定义的体检分、匹配分、面试报告、图表、预警始终由本地领域函数按当前快照产生。AIProvider 只返回**文本增强 payload**。页面 ViewModel=`当前领域结果 + 通过守卫的文本payload + 三态元信息`；不能把录制结果里的旧分数覆盖当前结果。

| 模块 | operation | Provider payload | UI 同时读取的本地结果 |
|---|---|---|---|
| A1 | rewrite | summary与suggestions[]，每条绑定resumeVersionId/fieldPath/before/after/evidence | 11 §3 的六维体检与ATS，版本对照 |
| A2 | question/followUp/feedback | sessionId,questionId,text,evidence[] | 题本/状态机/证据/rubric/报告；Provider不持有推进权 |
| A3 | explain | jobId,text,dimensionKeys[],skillIds[] | 11 §2 的MatchExplanation、What-if及排序 |
| A7 | query/advice | intent,text,metricRefs[],studentIds[],ruleIds[] | 作用域内当前指标、预警与帮扶表单 |

Schema 的 additionalProperties=false 禁止在 payload 私加 score、total、rate 等字段。A3/A7 文本数值使用 `{{metric:destinationRate}}`、`{{dimension:skill}}`、`{{match:total}}`、`{{rule:inactive7d}}` 等白名单占位符，由渲染器从本地值替换；A7分组指标可用15已登记的`{{metric:<metricId>:<groupAlias>}}`，不能模型自造token。模型原始文本不得自报当前统计数字。A1/A2 可引用用户原文数字，但新增成果必须由证据支持。

## 2. 统一响应与调用接口

AiResponse 的准确字段、必填与枚举以配套 schema 为准。所有态均返回：schemaVersion、algorithmVersion、promptVersion、traceId、inputHash、domainRevision、requestedMode、effectiveMode、origin、fallbackReason、usage、guard、data。

- requestedMode 是用户选择；effectiveMode 是实际出结果的态，两者不能混用。origin=`MODEL/RULE/CURATED` 记录文本来源，与播放方式不同；CURATED 必须标“人工审校示例”，不能声称真实模型调用。
- usage 未真实获得为 null；RULE/REPLAY 不生成虚假Token计费。guard.passed/masked 均为 true 才是成功响应；校验失败走类型化错误或降级，不伪造成功。
- 成功路径只允许requested LIVE→effective LIVE/REPLAY/RULE，requested REPLAY→REPLAY/RULE，requested RULE→RULE；effective LIVE必须origin MODEL，RULE必须origin RULE，REPLAY沿用语料真实来源且usage=null。Schema约束这些组合；guard仍由本地重签，不能接受模型自行封装的响应。
- Provider的Suggestion.disposition固定pending；accepted/rejected只由本地用户命令保存到建议处理记录，不能从模型或语料读取成“已采纳”。
- `AiRequest={module,operation,promptVersion:'1.0',schemaVersion:'1.0',algorithmVersion:'1.0',variables,domainRevision,signal?,epoch}`；variables 先脱敏；schemaId 从可信模块注册表选择，不接受 UI 任意覆盖输出Schema。
- `complete(req):Promise<AiResponse>`；`stream(req,onText:(delta:string)=>void):Promise<AiResponse>`。onText 只可显示于不可采纳的生成中预览，最终通过校验才出现采纳按钮。Schema 与语义校验失败须撤掉预览，不能当已保存内容。
- `AiFailure.code` 为 CANCELLED / PROVIDER_DISABLED / PROVIDER_CONFIG_ERROR / PAIRING_REQUIRED / PAIRING_FAILED / AUTH_FAILED / QUOTA_EXCEEDED / NETWORK_ERROR / UPSTREAM_ERROR / TIMEOUT / RATE_LIMITED / QUEUE_FULL / QUEUE_TIMEOUT / BUDGET_EXCEEDED / SCHEMA_INVALID / SEMANTIC_INVALID / INPUT_BLOCKED / RULE_FAILED；取消不返回 AiResponse。失败只写AiRun脱敏元信息。

UI文案分别为“模型生成·LIVE”“示例回放·REPLAY·来源MODEL/RULE/CURATED”“本地规则·RULE”；共同显示“请核实·可驳回”与依据。“AI”能力标签可以保留，但不能把RULE文本说成大模型生成。

## 3. 输入指纹与域版本

1. 从业务服务取得 scope 过滤后的不可变快照；不把整个 IndexedDB 交给模型。
2. 姓名/邮箱/手机号/证件/文件名用稳定占位符替换；拒绝未脱敏文本和外部URL内容抓取，未通过不能发LIVE。
3. 字符串NFC、统一换行为LF，不压缩会改变证据start/end的内部空白；undefined转明确null；集合型skillId数组排序去重，resume段落和答案数组保持顺序；只允许有限JSON数字、布尔、null和普通对象，拒绝孤立代理项。canonicalJson固定RFC 8785 JCS：对象key按UTF-16码元排序、ECMAScript数字序列化（-0为0、1.0为1）与字符串转义、无额外空白、UTF-8字节。先做本条业务规范化，再JCS；不能用Python默认json.dumps冒充JCS。前端canonicalize与Python rfc8785需用同一黄金夹具（中文/emoji、键序、0/-0、小数与指数）逐字节验证。
4. `domainRevision=SHA-256(canonicalJson(relevantSnapshot))`，无关用户操作不应影响本次请求；A1含当前简历版本/目标岗位/开关/strategy，A2含session当前题及已提交答案，A3含简历/岗位/权重/假设技能，A7含scope/query/asOf/指标值/预警和目标学生。
5. `inputHash=SHA-256(UTF8(canonicalJson({module,operation,promptVersion,schemaVersion,algorithmVersion,domainRevision,variables})))`；输出小写64位hex。traceId、发起时间、epoch、signal不入哈希；固定演示Clock与strategy入业务快照。

没有“相似输入随便回放”或按module取第一条的匹配。命中须 module/operation/三版本/inputHash/domainRevision全相等；任一改变直接RULE，避免编辑后出现旧评语/旧数值。证据位置针对脱敏规范化后的variables，回显原文仅在本地安全映射后完成。

## 4. 回放资产与来源登记

ReplayRecord 按 schema 存于未来项目 `src/data/replay/*.json`；Provider 位于 `src/adapters/ai/replayProvider.ts`，不另建 `src/ai/` 第二套接口。语料包含审核人标识/审核时间、origin、versions、指纹、payload与chunks；不存会变的traceId或当前分数。payload.module/operation须与记录一致，跨模块记录拒绝加载。

不准备真实API Key仍可制作RULE或人工审校CURATED语料；不得把它们伪写为MODEL录制。MODEL语料必须保留脱敏来源记录和人工核对，不必保存原始敏感prompt。REPLAY资产本身无需付费录制；v1.5新增的真实接入验收需用户许可后另行完成，不用回放资产替代。

每模块至少2组业务场景，A1含structure与keepMyTone分支；A2覆盖完整3主题及每题最多2追问、弱回答/跳过/续答，至少10条operation记录；A3含高/低匹配及What-if失配退RULE；A7含问数与高风险建议。至少一条故意过期domainRevision、一条不合法schema作为测试夹具，不能混入可加载清单。

chunks的t是0–3000ms相对偏移，非递减，第一条t=0；text拼接必须等于 `renderText(payload)`：A1为summary，有建议时追加LF及按顺序用LF连接的after；A2/A3/A7为text。A1允许suggestions为空：无可改写原文或无需改写时只给summary，不伪造问题/引用/无意义改写。按完整Unicode字符切片，不切开emoji代理对；最长3秒，可跳过。回放模拟分块而非真的HTTP/SSE，报告明确区分。

## 5. 降级、取消与预算

| 情况 | 动作 |
|---|---|
| 默认REPLAY、语料命中且校验通过 | 在REPLAY输出，不因断外网主动切RULE |
| REPLAY不存在/版本过期/Schema或语义失败 | effectiveMode=RULE，fallbackReason明确记录；RULE按当前快照出结果 |
| LIVE未启用/未配置Gateway | 不发网络请求；requestedMode=LIVE，提示未配置，再REPLAY→RULE |
| LIVE网络/认证/额度/429/5xx/总耗时到限 | REPLAY→RULE；不自动重复可能计费的请求 |
| LIVE结构/语义不合法 | 丢弃，REPLAY→RULE；“再生成”须用户主动动作，不自动付费自修复 |
| AbortSignal/离页/角色切换/复位/新请求替换 | 取消并写cancelled；不启动任何fallback，不覆盖后来的结果 |
| RULE自身错误 | 显示明确错误+重试入口，保留已保存业务数据；不能兜底伪造非空结果 |

LIVE出队后总上限8秒（含连接/流式读取），排队最多8秒；禁止自动重试；active并发最多2、等待最多4。单请求completion<=1200 tokens、input<=12000规范化字符；网关每60秒最多10次、进程最多20次上游尝试、累计10000 tokens软停止阈值。真实usage未知保持null，本地用实际messages总字符数（含系统提示）+输出上限作保守扣账，不伪造计费。测试也占配额，配对/角色切换不重置，网关重启会清预算；不是硬金额或硬Token保证。网关为全局准入权威，不堆叠隐藏队列，完整预算/预占/错误/连接测试规则以15 §6为准。付费失败或不明状态不自动再发。

每请求捕获epoch与domainRevision；回包前验证当前epoch、当前用户与版本仍相等，失效则丢弃、不写领域对象。保存结果和修改业务都是用户显式命令；Provider只有读数据与追加AiRun权，不触发投递、审核或签约。

## 6. 语义守卫（Schema 之外必做）

- A1 before必须逐字等于当前版本字段；evidence.quote=source.substring(start,end)；after中新增数字或实体无证据时改为占位并 requiresUserInput=true；未改变职责程度；有占位不可采纳。
- A1 fieldPath固定basic.name/basic.email、experience.<稳定条目id>.description、projects.<稳定条目id>.description中的允许字段；MVP生成改写仅后两种描述，basic只读引用，其他段由规则给提示。解析器按类型白名单定位，不用eval或任意属性链，拒绝__proto__/constructor等路径。start/end按规范化字符串UTF-16索引（JS substring），必须落完整Unicode边界；本地证据映射不能改变被引原句。
- A2 sessionId/questionId必须属于当前会话，feedback的证据只能来自该题已提交答案；题目不能重复、追问数不能超过2；数值只取本地rubric。
- A3 jobId必须在当前可见岗位集，dimensionKeys/skillIds存在且被当前解释引用；占位token在模块白名单内。
- A7 studentIds全部在当前scope，ruleIds确实触发，metricRefs存在于本次聚合结果；未知intent用clarify，不由模型自行扩大查询范围。
- 所有文本作为textContent/插值渲染，Markdown/HTML/脚本标签不执行。引用、内部路由只从允许ID生成，不信任模型URL。恶意简历/JD中的“忽略指令”等仍当数据，不当系统指令。
- 新增敏感字段需更新脱敏与清除测试；AuditLog不保存未脱敏输入。模型输出的“passed=true”不可信，guard必须由本地守卫签写。

## 7. 真实 Gateway 的边界

v1.5按用户D-15确认升级为正式交付：首适配DeepSeek、独立网关配置、统一启动/配对/显式付费连接测试，运行默认仍REPLAY。网关是本机AI网络适配，不是业务后端。凭据/端点/Origin/配对/错误与SSE的唯一详细定义见[15](15_真实AI接入与本机运行契约.md)，避免维护两套协议。浏览器只发送规范化wire请求，不发送Key或任意上游URL；网关只返回真实LIVE或安全错误，fallback由浏览器负责。

三态成功结构沿用现有Schema 1.0；新增AiFailure类型与网关wire是调用契约细化，不修改既有回放成功payload或业务算法/种子版本。GW11须验证四模块effectiveMode=LIVE且双守卫通过，最迟G5；无Key只能证明离线与mock边界，不足以声称真实联调成功。

## 8. 文档契约的验证方式

当前阶段验证配套JSON可解析、Schema结构合法、全部本地$ref可解析、合法样本通过、含score等非法字段样本失败；12的语义不变量交由13中的AI测试在开发期实现。Schema验证通过不代表已有Provider或真实模型联调；Provider/回放及网关mock证据由14的M3/G3产出，A7接线在M4、真实四模块联调最迟M5/G5。
