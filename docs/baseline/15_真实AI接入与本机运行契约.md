# 15 · 真实 AI 接入与本机运行契约

> 路鸣职引 CareerPilot · v1.5 · 2026-11-12 · gatewayVersion=1.0
> 用户已确认本方案，仅授权完善文档；本轮不创建应用、配置真实密钥、安装依赖或调用模型。本册是接入、启动与凭据边界的唯一详细规格；12仍是业务AI响应、守卫与回放的权威。

## 1. 范围与完成定义

**真实AI接入是正式Must交付项，不再是可以不实现的扩展。** 首个且本期唯一承诺适配的供应商为DeepSeek官方API。四模块A1/A2/A3/A7均须能请求真实模型，并沿用12的文本payload和本地数值内核。其余供应商只保留适配边界，不承诺任意“兼容API”填Key就可用，不自动换厂商或模型。

“代码可配置”与“真实联调通过”分开：无Key可以开发与运行离线功能、完成网关mock测试；G3可在真实联调未执行时注明条件放行，继续无外部凭据依赖的M4。**G5完整验收必须有用户明确同意后的四模块真实LIVE证据，不能用stub、连接测试或fallback代替。** 未提供凭据/调用许可时标not_run并列出外部依赖，不冒称完整交付。

不改变品牌、Vue/TS/Vite、四角色、单机IndexedDB、A1/A2/A3/A7及REPLAY答辩默认。网关不保存业务数据库、不提供招聘CRUD、不接旧C++程序、不变成多人平台。

## 2. 架构与依赖

```text
浏览器 http://127.0.0.1:4173（Vue + IndexedDB）
  → 已配对的本机 http://127.0.0.1:8787（FastAPI）
  → HTTPS https://api.deepseek.com/chat/completions
```

网关独占读取凭据、构造系统提示词、限制上游地址、调用与错误映射；前端不能传apiKey/baseUrl/model/任意messages/任意schema。业务快照仍由浏览器scope过滤、脱敏与最小化。网关校验请求、输出Schema和可从本次variables验证的语义；浏览器最终再按当前实体、scope、epoch与domainRevision校验。模型不创建AiResponse外壳或自签guard。

前端/离线运行依赖保持14的Node>=22.12且<25、npm>=10且<12。LIVE另外要求Python>=3.11且<3.14及预装的专用venv，候选库为FastAPI、Uvicorn、httpx、python-dotenv、jsonschema、rfc8785、pytest；前端用canonicalize实现同一JCS。开发时解析兼容版本并生成精确锁定文件，不能把本规范当已安装记录。直接用httpx构造请求，显式关闭重试、重定向与环境代理继承，验证TLS证书；不借用SDK隐藏重试。

## 3. 配置、凭据与首次使用

### 3.1 唯一配置位置

未来应用使用`careerpilot/gateway/.env`；仅Python网关进程读取。不是前端根目录`.env`，不是`VITE_*`，不是`src/`、`public/`或`dist/`。进程环境中的同名变量优先于该文件；只输出“使用进程配置/文件配置”，不回显值。修改后重启网关，不支持网页写Key或热重载。

未来应提供以下**空凭据模板**`gateway/.env.example`，本轮不创建运行文件：

```dotenv
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-flash
AI_API_KEY=
AI_LIVE_ENABLED=false
```

| 配置项 | 规则 |
|---|---|
| AI_PROVIDER | 固定deepseek；其他值报PROVIDER_CONFIG_ERROR，不猜测服务商 |
| AI_BASE_URL | 固定HTTPS官方主机api.deepseek.com，允许结尾/；规范化后只拼接一次/chat/completions；拒绝userinfo、查询、片段、非443端口、私网/IP及重定向 |
| AI_MODEL | 默认deepseek-flash，可改为同一供应商当前账号可用的非空模型ID；最长100字符，仅ASCII字母/数字/点/下划线/连字符；不静默切换或回退模型 |
| AI_API_KEY | 默认空代表未配置；只有启用LIVE时才要求去首尾空白后非空且无换行；只做本地格式检查，不能假定所有Key有同一前缀；有效性由显式连接测试确认 |
| AI_LIVE_ENABLED | 仅true/false，默认false；填Key不等于同意发起请求，启用网关不等于自动选择LIVE |

配置错误只报字段名及安全原因；不得打印对应值、Authorization或异常原始请求。上游地址不接受网页任意配置，防止本地服务变成任意转发代理。更换供应商须另增适配器、来源记录与契约测试，不在本期扩大范围。

### 3.2 使用流程

1. 开发交付后，用户在本机把空模板复制为`gateway/.env`，填写自己的API Key；默认地址/模型预填。密钥不需要发到聊天中。
2. 将AI_LIVE_ENABLED设为true，完成一次性的Python/venv依赖预装；日常启动不再安装、不再改源码。运行统一入口`start-project.cmd`。
3. 网关在本机终端显示一次性配对码；在全角色壳的“本机AI连接”弹窗配对，P16同时提供状态面板。配对依赖终端持有码而非教学管理员角色，各角色均不获取上游凭据。
4. 点击明确标注“将调用供应商API，可能产生费用”的连接测试。无业务数据，只发送固定最小测试提示词，最多32输出tokens；一次点击一次请求，失败不自动重试。
5. 测试通过后由用户手动启用本次浏览器会话的LIVE，并在具体功能确认脱敏发送预览。四模块共享连接，不重复填写Key。每次启动默认仍REPLAY，不自动付费调用。

配置只需填一次；每次重启网关需重新配对，刷新网页/令牌过期后须由本机重启网关取得新码，**不需重填上游Key**。连接测试成功仅表示当时可调用该配置，不保证后续余额/网络，也不等于任何业务模块已通过验收。

### 3.3 保密与交付

`.env`是明文配置，不是加密存储；只适合受信任的本机教学环境。文件权限限制为当前用户，禁止屏幕分享、日志或报告回显。网关凭据既不进入IndexedDB/localStorage/sessionStorage，也不通过API返回；短期配对令牌仅在前端内存，不能混同上游Key。

未来`.gitignore`同时忽略根/嵌套`.env`与`.env.*`，显式允许空`.env.example`；忽略gateway/.venv、日志、artifacts中的私有原始网络记录。打包采用文件允许清单，不依赖gitignore自动保护：源码包只附模板与锁文件，离线demo只附静态产物和启动器。不得把真实配置放入报告、ZIP、source map、前端资源或共享盘。泄露后先在供应商撤销/轮换Key，删除仓库当前文件并不能撤销历史泄露。

静态服务只开放dist或demo/web的内容，不以careerpilot工作区为Web根；`/gateway/.env`及路径穿越必须404/拒绝。网关不开启含请求体的debug/access日志、异常页或公开/docs、/redoc、/openapi.json；错误响应和证据只保留脱敏类型码。

## 5. 配对与受限端点

固定浏览器Origin仅`http://127.0.0.1:4173`；不接受`*`、`null`、其他Host/Origin或携带cookie认证。Host限制127.0.0.1:8787，拒绝DNS重绑定；OPTIONS仅放行指定Origin、GET/POST及Content-Type/Authorization，JSON POST必须application/json。所有非health端点要求该Origin，缺失也拒绝；只有本机启动探测GET /health允许无Origin。Origin/CORS不是身份认证；受保护接口还必须有Bearer配对令牌。此机制不抵御设备拥有者或恶意本机进程，不宣称生产认证。

配对码为密码学随机8位数字，启动后5分钟有效、一次使用、最多5次错误尝试；错误只返回PAIRING_FAILED。成功换取随机>=256bit的不透明令牌，只在内存存摘要、绑定当前网关实例、有效30分钟，网关重启失效。配对码仅显示在本机终端交互区，不进入持久日志或证据；不得放URL查询参数。前端退出/复位/停用清除令牌并回REPLAY；角色切换仅取消请求/清外发同意，不必销毁有效本机配对；不在浏览器持久保存。

| 方法 / 路径 | 认证 | 请求与成功响应 |
|---|---|---|
| GET /health | 无令牌；仍校验Host/Origin | 200 `{status:'ok',gatewayVersion:'1.0'}`；不返回配置或Key，供启动就绪检查 |
| POST /api/pair | 配对码 | 严格body `{code:string}`；200 `{token:string,expiresAt:ISO8601,gatewayInstanceId:string}`；失败401 |
| GET /api/ai/providers | 配对令牌 | 200 `{providerId:'deepseek',model:string,configured:boolean,liveEnabled:boolean,gatewayInstanceId:string}`；无Key或其片段、无环境转储；configured仅格式正确，不代表验证有效 |
| POST /api/ai/test | 配对令牌 | 严格body `{confirmPaidCall:true}`；200 `{status:'passed',providerId:'deepseek',model:string,latencyMs:number,usage:{prompt:number,completion:number}\|null}`；验证上游真实非空结果，不进行业务降级 |
| POST /api/ai/structured | 配对令牌 | 下面定义的业务请求；200为12完整AiResponse，effectiveMode=LIVE、origin=MODEL；失败为安全错误，不在网关生成REPLAY/RULE |
| POST /api/ai/chat | 配对令牌 | 同一业务请求；200为下述SSE；流前错误用HTTP，流中错误用error事件 |
| POST /api/unpair | 配对令牌 | 严格空body `{}`；204并吊销当前令牌、取消所属请求；前端即使请求失败也清理内存并回REPLAY |

HTTP错误统一为`{error:{code:string,traceId:string,retryable:boolean}}`，无额外字段。traceId由网关生成或验证可信请求ID，不包含Key；retryable只表示用户可以主动重试，绝不触发自动重试。配对失败不揭示码是否过期/接近正确；令牌过期返回401 PAIRING_REQUIRED。

业务wire请求严格为`{gatewayVersion:'1.0',traceId,module,operation,promptVersion:'1.0',schemaVersion:'1.0',algorithmVersion:'1.0',inputHash,domainRevision,variables}`，拒绝额外字段；module/operation取12的允许组合，hash为小写64hex，traceId为1–100字符的非敏感ASCII标识。variables是12规范化后的最小业务变量，不含signal/epoch/Actor令牌。浏览器本地维护epoch，网关按12的RFC 8785 JCS复算inputHash，哈希不符返回INPUT_BLOCKED；domainRevision由浏览器从完整相关快照算出，网关只验证格式/透传，不伪称能验证未持有的全库scope。

variables固定为以下四种结构，所有对象additionalProperties=false，列出的字段必须存在，允许空值的明确写null。Id、Instant、Evidence与值对象复用10–12；所有文本先NFC/脱敏，ID只能是本次请求的稳定匿名别名，原ID映射留浏览器。不能将全库、附件、原始个人标识或任意系统提示词装入variables。

| 模块 | variables准确结构 | 额外约束 |
|---|---|---|
| A1 | `{resumeVersionId:Id,fields:{fieldPath:string,text:string}[],targetJob:{jobId:Id,title:string,jdText:string,skillIds:Id[]}\|null,strategy:'structure/evidencePrompt/concise',keepMyTone:boolean}` | fields只含experience.<id>.description或projects.<id>.description，最多20条；text为当前字段完整脱敏原文、每条<=4000字符；空简历允许[]；before/evidence必须引用其中字段，ID先映射后恢复 |
| A2 | `{sessionId:Id,question:{questionId:Id,type:'behavior/technical/hr',text:string,skillIds:Id[],keywords:string[]},followUpCount:integer,answers:{id:Id,kind:'answer/followUp/skip',text:string}[],jobContext:{title:string,skillIds:Id[]}}` | followUpCount为0–2，answers只含当前题最多3次已提交回答、每条<=4000字符；questionId/评分标签不得改；Evidence.fieldPath为answers.<id>.text，题目措辞操作不得生成新ID |
| A3 | `{job:{jobId:Id,title:string},match:MatchExplanation,hypotheticalSkillIds:Id[]}` | match准确值对象见11 §2，包含六维贡献/真实hits/misses及技能缺口；jobId须一致，仅当前选中岗位，不发全库；假设技能单独标注，不能包装成已掌握 |
| A7 | `{queryText:string,intent:MetricIntent,scopeLabel:string,asOf:Instant,metricContext:{metricId:MetricId,token:string,label:string,value:number\|null}[],targetStudents:{studentId:Id,riskLevel:'low/medium/high',ruleIds:RuleId[]}[]}` | queryText<=500，scopeLabel为匿名范围别名；query时targetStudents=[]，advice只准一个目标学生；风险/数值来自本地；MetricIntent、MetricId为Schema A7枚举（intent含clarify），RuleId为四预警枚举 |

A7将六意图需要的标量或分组拆成metricContext最多100行，value只为有限数/null，不传任意JSON/SQL。每行token为`{{metric:<metricId>}}`或分组token `{{metric:<metricId>:<groupAlias>}}`，groupAlias仅ASCII字母/数字/下划线/连字符、1–64位，token全表唯一；byMajor/funnel等分组标签先脱敏。输出只能引用本次登记token，metricRefs仍只用既有六MetricId枚举。模型不得自行计算统计/风险或扩大scope。

共享字符串上限：Id沿用Schema的1–160字符，traceId另按上述100字符限；title/label/scopeLabel<=200，jdText<=4000，题目<=1000，关键词/技能名<=100；普通ID数组最多100且去重。12000字符限指JCS(variables)的Unicode码点数，64KiB限为完整HTTP正文UTF-8字节数；网关系统提示词+user消息另检查模型上下文上限。超限须用户缩小范围而非静默截断证据。Evidence.start/end独立按JS UTF-16索引；hash按规范化后JCS的UTF-8字节。前端与Python使用同一黄金夹具验证键序、数字序列化、UTF-16证据边界和hash，不是两端各猜一套输入字段。

浏览器用fetch+ReadableStream读取POST SSE，不用只支持GET的EventSource；网关显式StreamingResponse。事件id从1递增，只有`text_delta`、`final`、`error`三种：data分别为`{delta:string}`、完整AiResponse、上述error对象。final/error互斥且最多一次；EOF无终态视为UPSTREAM_ERROR，final后额外业务事件拒绝。HTTP/network分块不等于SSE事件；正确处理拆开的UTF-8、多行data、CRLF和尾部[DONE]（仅上游协议，不直接转发成业务final）。

上游生成JSON文本；text_delta只用于不可采纳的结构化生成预览，默认UI可只显示生成中，不能把半截JSON当业务正文。缓存完整内容后解析payload、检查Schema/语义、由网关组装AiResponse，浏览器再次守卫才展示renderText及采纳按钮。中断时撤销预览，不保存半个结果。

## 6. DeepSeek适配、错误与预算

### 6.1 调用策略

请求用Bearer上游Key、固定POST /chat/completions；system提示由模块注册表提供，明确要求JSON及合法payload示例，user仅承载脱敏variables。设置`response_format={type:'json_object'}`、`thinking={type:'disabled'}`、`max_tokens<=1200`、stream依对应接口选择，不启用工具调用、联网搜索、文件上传或思维链展示。连接测试使用固定短提示与max_tokens=32，不要求业务Schema。JSON模式只保证JSON语法，不保证本项目Schema；空内容、finish_reason=length或非stop、截断、错字段均拒绝，不自动再请求“修复”。完整流须同时收到合法finish_reason及上游[DONE]才视为完成，不能在半途JSON恰好可解析时提前final；非流式也要求正常结束。

12的8秒LIVE总限从请求出队开始，包含连接/上游生成/流式读取，使用单一单调时钟deadline，而非每块各8秒；连接限2秒且不延长总限。客户端额外最多1秒接收/本地校验宽限，随后主动取消。队列等待最多8秒，超时QUEUE_TIMEOUT且不发上游；客户端从发送起最多17秒（8秒排队+8秒处理+1秒宽限），不能每个delta重置。无排队时总处理仍限8秒。同一请求不重复入队。上游非流式/累计SSE响应最多256KiB，超出或非法编码按UPSTREAM_ERROR拒绝。网络断开/Abort应关闭上游流；这只能阻止后续消耗，不能保证供应商退还已产生费用。

### 6.2 错误映射

| 触发 | 类型码 / HTTP | 前端行为 |
|---|---|---|
| 未启用/无Key | PROVIDER_DISABLED / 503 | 明示未配置，业务请求REPLAY→RULE；连接测试明确失败 |
| 地址、模型配置非法/上游400、404、422 | PROVIDER_CONFIG_ERROR / 400 | 提示检查配置；不原样回显上游消息，不换模型 |
| 上游401/403 | AUTH_FAILED / 401 | 提示Key或权限问题；停止继续LIVE，需用户修改/重启/测试 |
| 上游402 | QUOTA_EXCEEDED / 402 | 提示余额/额度不足；停止继续LIVE |
| 上游429/本机10次每分钟限制 | RATE_LIMITED / 429 | 不自动重试，用户可稍后主动再试 |
| 并发队列已满/等待超时 | QUEUE_FULL / 429；QUEUE_TIMEOUT / 504 | 不发上游，提示忙碌，可取消 |
| 8秒总限 | TIMEOUT / 504 | 关闭上游连接，业务fallback；不声称未计费 |
| DNS/TLS/断网/连接失败 | NETWORK_ERROR / 502 | 业务fallback；不忽略证书错误 |
| 上游5xx/异常协议/流无终态 | UPSTREAM_ERROR / 502 | 撤掉预览并fallback，不泄露原始错误body |
| JSON/payload或语义不合格 | SCHEMA_INVALID / 502；SEMANTIC_INVALID / 502 | 丢弃原始输出并fallback，不自动付费自修复 |
| 请求太大/脱敏或指纹不符 | INPUT_BLOCKED / 413或400 | 不发送上游，要求修改输入；恶意内容不得绕过守卫 |
| 预算门槛触发 | BUDGET_EXCEEDED / 429 | 停止后续LIVE并提示本地回退 |
| 用户取消/断开/失效epoch | CANCELLED（客户端本地终态） | 不fallback；不要求已断开的连接再返回HTTP错误 |

PAIRING_REQUIRED只要求重新配对，不当作供应商Key错误。业务fallback统一由浏览器编排器执行并记录上述fallbackReason；网关不在失败时伪造MODEL成功。网关实例内已接收的业务traceId保留到退出，重复ID拒绝为INPUT_BLOCKED且不再次排队/发送上游；每次用户明确“再试”是新traceId。无自动付费重试、重连重放或跨供应商容灾。

### 6.3 配额与诚实计费

网关进程统一执行：活动上游最多2、等待最多4、滑动60秒最多10次尝试、进程生命周期最多20次上游请求（含连接测试/失败），每请求input<=12000规范化字符且HTTP正文<=64KiB。前端显示“等待AI响应”并提供取消，不虚构排队位置、不额外排一层LIVE等待；REPLAY/RULE的本地队列不占上游预算。以网关最终准入为准，测试也占用并发和预算。

累计真实usage的prompt_tokens+completion_tokens达到10000后停止接收后续LIVE；usage缺失/已发送但失败不明时按本次实际发送messages总字符数+输出上限作**保守本地估算**扣账（包含网关系统提示词，而非仅variables），但AiResponse.usage仍null。只做预检而尚未发上游的失败不计费用预算。流式usage从供应商终结块取得，不能假定另有空choices的usage专用块。

10000是事后统计的软停止阈值，不是供应商侧硬Token/金额上限：单次输入、最多两个在途请求及缺失usage估算可能超出。未完成在途请求预占输出上限，准入时计入预算；最终用实测/保守值结算。配对、角色切换和重新测试不清预算；网关重启会清本地计数，UI必须提示。需要硬金额控制时使用供应商控制台预算/余额管理，不虚构人民币费用或“绝不会超额”。

## 7. 界面、隐私与证据

P16增加“AI连接”区，仅显示供应商、模型、未配置/待配对/待测试/可启用/运行中/失败状态、脱敏类型码、测试/停用按钮及费用提示；所有角色壳提供同一连接弹窗，允许持有本机终端码的操作者配对。**不新增网页Key输入、读取、保存、导出接口**。配对独立于教学角色且不持久化：切角色取消旧请求、清外发同意、回REPLAY，但有效本机令牌可保留；显式退出/复位/停用或网关重启清令牌。这样无需每切一次角色就重启网关，且不复用前一角色的脱敏快照或外发授权。

每次外发前展示最小脱敏内容与供应商/模型、所用功能、可能产生费用；用户主动确认才发送，默认不持久化同意。A2默认同样逐请求确认；可在开始时另外显式同意“仅本次模拟面试会话内、预览已说明字段及本人后续输入”的请求，暂停/切角色/退出/复位/更换模型/会话结束即撤销，不扩展到其他模块。拒绝确认不发网络且保留本地功能；不能把配置Key、连接测试或打开页面视为授权发送整份简历。A7默认仅聚合；针对个体帮扶只传必要规则/匿名ID，不发送全班简历。附件始终不发送。

停用LIVE应先取消所属请求，用即将丢弃的令牌尽力调用unpair，随即清预览/令牌/同意状态并切REPLAY（不等待网络）；不能先丢失令牌再尝试认证请求。不删除gateway/.env中的Key，避免误以为网页删除了本机凭据。需移除Key时用户在本机清空配置并重启；疑似泄露则到供应商撤销。reset-demo取消请求、回REPLAY并清本地配对状态，不偷偷改配置文件或触发连接测试。

真实联调使用虚构脱敏样本、用户本机提供的有效配置及明确费用许可；每模块至少一次effectiveMode=LIVE且guard通过。A2至少验证题目/追问/反馈三类operation；A7至少验证问数解释与帮扶建议。证据记录runId、traceId、供应商/配置模型、gatewayInstanceId、时间/延迟、usage或null、Schema/语义断言和本地数值前后不变，不保存Key/配对码/令牌、完整请求头或敏感HAR。模型别名可能滚动升级，报告区分配置ID与供应商实际返回的model（能获得时记录），不声称别名锁定具体模型权重。
