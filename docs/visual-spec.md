## P01

- 采用概念图的左右双区构图：左侧品牌叙事、右侧四角色及一个明确的进入动作。白色选择区，冷浅灰外底，深蓝品牌区；375 屏转为上下结构。
- 主文案：每一段探索，都有方向；角色选择文案、四张角色卡及按钮采用 prompt 文件中的完整文字。
- 徽记保留 05 §10 原有路/声波/引导星点，不采用生成图误造的灯塔 logo；品牌名以规范为准，不采用图片文字识别错误。
- 真实文字、角色卡、主题按钮、进入操作均原生 Vue，非图片热点。
- 概念中的海岸插画需要独立生成。第一次独立插画请求连接错误，状态可能不明，禁止付费重试。暂用品牌的原生路径/声波线条组成安静的航路图案；这是已记录的素材阻碍/有意偏离，不声称还原插画。
- 角色卡为 2×2，1280 保证四角色与进入操作首屏可见；不加密码、搜索、通知、虚构指标。

## P02 / P18

- P02：240px 导航，大屏保留，1280 收为 64px，移动端抽屉；独立顶栏、面包屑、真实角色与来源状态，不制造业务数据。
- P18：延用 05 §11 精确双主题 token；大标题与开放式排版节奏、颜色带、字体展示、组件交互演示、品牌规范，避免每段包一张同样的卡片。
- 组件：按钮、输入、选择、标签、面板、焦点锁定 Modal/Drawer、Toast、Skeleton、空/错误状态。可用键盘完整操作，Esc 关闭并归还焦点。
- 图标统一 24 viewBox、1.6 stroke、round join/cap，不用 emoji 替代功能图标。
- 正文14–16、标题24–40、控件14，4px间距阶梯；A/B各完整 token；打印去导航/控件、禁动画。

## 全站变化原则

按文档页面族分设计：学生首页叙事+聚合、简历编辑器、岗位列表+解释抽屉、面试对话+证据、企业招聘工作台、辅导员名册/审核、深色数据驾驶舱和克制的治理控制台。共用字阶与组件，但不复用同一张仪表盘模板；全部必做页面族均已实现。

## 后续视觉要求 D-20 · 场景化素材与角色自主图片管理（未实施）

2026-11-13 用户明确补充：当前页面渲染显得生硬乏味，后续应在适合的场景使用生成图片或合规网络图片，实际嵌入页面代码；必要模块允许相应角色按需接入自己喜欢的图片。此项是后续改造要求，不代表本轮已生成素材、开放上传或完成页面改造。

### 场景与整体表达

- 图片须与毕业生就业服务、校园成长、职业探索和多角色协作相关，承担叙事、内容识别或情境引导作用；不只反复堆叠几何色块，也不为每页强加大背景图。
- 延续路鸣职引 / Lighthouse 品牌、色板与控件语言，通过不同场景、构图、照片和插画形成变化；避免各角色页面套用同一张素材、同一种卡片模板。
- 素材应作为真实图片资源接入组件，适配桌面和手机裁切。正文、按钮、表单、数据图表与功能操作仍原生实现，不用整页图片模拟交互。
- 候选位置包括公共首页和登录的场景主视觉、指导与活动封面、企业品牌展示及有意义的空状态；后台密集办理区以清晰易用为先。具体位置、数量和风格留待逐页审阅，不视为全部扩展功能已批准。

### 角色自主选图的后续边界

- 按模块权限提供“上传或素材库选择 → 预览/裁切 → 保存 → 更换、移除或恢复默认”的能力。学生头像/个人封面、企业标志/品牌图、授权发布者的活动/内容封面为候选范围；管理员负责获授权的公共素材治理，不允许所有角色任意修改全站图片。
- 学生个人形象图片应为自愿使用，不成为投递必填条件；企业图片按组织归属管理。个人私有图片与公开展示分别授权，上传不等于同意对外公开。
- 用户所说“实时随机接入”本阶段按随时自主选图、更换和即时预览记录；自动随机轮换、任意网址抓图或运行时付费生图并非默认授权。如需要素材库随机挑选，后续另定可选范围和触发方式。
- 即时本地预览不冒充服务器保存成功。在线版保存素材引用、所属角色/组织和版本，并仅向有权限的设备同步已提交变更；冲突、失败和权限变化有明确反馈。

### 素材来源、质量和安全

- AI 位图默认使用用户指定的 `skill-1k`；实际生成前读取现行技能，遵守凭据与费用边界，失败或结果不明不自动付费重试、不静默切换供应商。本轮不调用生图服务。
- 可使用用户有权提供的图片、自有素材和许可允许该用途的网络资源；记录来源链接、作者、许可、必要署名和使用范围。网上可查看不等于可复制交付，截图或裁切不消除版权义务；不得擅用他人肖像、商业页面整图或专有插画。
- 上传须在服务端校验实际内容/MIME、格式、体积和尺寸，处理危险文件和 SVG 脚本风险，移除不必要的 EXIF 定位等隐私元数据；按用途设置配额、公共内容审核与删除机制，私有媒体受控访问。
- 统一图片比例、焦点裁切、压缩与响应式尺寸；非首屏按需加载并预留空间，提供合适替代文本和加载失败回退，不能牺牲正文对比度、移动端可读性和首屏速度。

后续改造先读取本节，并与 `portal-homepage-design-plan.md` 的素材流程及 `online-upgrade-strategy.md` 的服务端权限/文件存储策略共同执行。视觉验收应包含图片适配、角色自主替换以及空/失败状态，而不仅检查静态样图。

## 全站视觉复核 D-21 · 统一语法，按场景识别（已记录，暂不实施）

用户以企业商标嵌入示例要求进一步统一全站界面与布局，同时合理创新、杜绝千篇一律。检查结论、候选路线与逐模块映射保存于 `docs/visual-unification-review.md`。

- 推荐统一底层规范与五类语义识别：企业/组织、个人、内容/文档、流程/成长、来源/数据；平台品牌不等于企业商标，功能图标不等于身份标志。
- 同一对象跨页连续识别，不要求所有模块都加图。演示企业使用原创虚构标识，真实企业素材须核验使用权；不把示例中的真实商标配给本项目虚构企业。
- 本次源码与代表页面抽查发现重复大页头、按钮/状态标签拉伸、名单默认边框、组合搜索双边框及小评分字号等待改问题，优先处理布局比例再扩展素材。
- 本轮为审查与方案提案，待用户确认方向后进入正式规格、视觉概念与实施；不将这些待改项写成已修复，也不替代全站视觉验收。
- 用户随后明确先记忆方案、暂不动源码，待下一开发阶段再全链条执行。当前仅保留设计输入，不启动实现或生图；届时应覆盖素材、组件、各角色页面、权限/同步衔接和视觉/功能验收，不止局部美化。
