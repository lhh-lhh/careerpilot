## 1. 后续开发必须继承的目标

**D-24 第四阶段更新（2026-11-14）：** 默认在线启动/独立空业务初始化五账号；学生企业审核、员工邀请、改密撤会话及持久限流已实施。NCSS仅有限链接索引，不冒充本站发布或完整匹配。411单测、114双浏览器功能与新库招聘至去向/恢复链通过；本机4174已运行，密码仅本机私有保存。PostgreSQL、生产TLS/目标设备负载、身份名单/字典、文件扫描/留存、真实AI与原P2/P3仍未放行。见 `stage-four-runbook.md`、`stage-four-issues.md`、`evidence/stage-four.md`；以下历史现状不能覆盖本次事实，本次本机账号实现也不是整条路线完成。

1. 保持“毕业生就业管理与智能服务”的定位，覆盖学生、企业、辅导员、管理员，不改成单纯招聘网站或通用聊天工具。
2. 保留 HTML/CSS/Vue.js 前端方向。当前 Vue 3、TypeScript、Vite、Pinia 和组件设计系统可继续使用；增加后端不改变前端技术合规性。
3. 多用户、多角色可在不同设备同时联网使用，共享业务事实，并在各自权限内及时看到相关变更。
4. 从离线教学演示升级为可小范围实际试用的应用；不能将同浏览器多标签同步当作跨设备在线协作。
5. 服务端预留用户后续提供的 DeepSeek API Key 配置能力，完成真实智能在线交互，而非仅有规则模板或回放；费用授权与真实效果验证单独执行。
6. 全站界面美观是主要验收指标之一。共享品牌与交互规范，各角色按工作任务形成不同布局，避免所有页面复制同一种卡片仪表盘。
7. 两张参考图是需求线索，不是唯一方向或全量实施清单；原始需求、已实现事实、新增建议必须区分。
8. 后续新增统一公共首页：打开主网址先看到与就业服务相关、有原创识别点的公共门户，再与登录及四角色工作台自然衔接。设计与分期见 `portal-homepage-design-plan.md`，当前尚未实施。
9. 场景化图片应实际接入页面，必要模块支持相应角色自主上传、选择和更换素材；在线版需同步设计素材所有权、组织作用域、公开许可、上传校验与受控存储。具体视觉与权限要求见 `visual-spec.md` 的 D-20，当前尚未实施，不默认授权运行时付费生图或任意网络抓图。

本文件是项目内的持久记录，不宣称模型具有无条件、跨会话永久记忆。后续继续开发时应先读取本文件和 `role-workspace-assessment.md`；与冻结基线冲突的内容登记为后续变更，不覆盖 `docs/baseline/`。

## 2. 当前事实与不应作出的承诺

- 权威数据在浏览器 Dexie/IndexedDB；用户、企业、组织和时钟为演示夹具；角色选择不是生产登录。
- `src/services/app-services.ts` 的 BroadcastChannel 只在同源、同浏览器存储分区内通知标签页；异地设备没有共同数据库。
- `src/stores/aiConnection.ts` 使用 `127.0.0.1:8787` 本机网关；手机中的 `127.0.0.1` 指手机本身，不指开发电脑。
- DeepSeek 适配代码已存在，但没有可证明真实上游成功调用的 GW11 样本。规则/回放和上游输出必须继续区分。
- 当前模拟面试题本与追问来自本地题库/规则，报告的 feedback 才接入业务 AI 通道。业务 AI 目前调用 `live.complete`，界面分段显示不能等同于完整上游流式。
- 历史单机自动测试结果不能证明互联网安全、真实身份权限、并发容量、跨设备同步或真实 AI 质量已经达标。
- 仓储和命令实现直接依赖 Dexie；不能仅修改数据库连接字符串、替换 IP 或开放 Vite 端口就完成升级。

## 3. 推荐架构：保留前端，重构可信数据边界

推荐初期使用模块化单体，避免在小规模试用阶段引入不必要的微服务运维。

| 层级 | 推荐职责 | 现有资产如何处理 |
|---|---|---|
| Vue Web 前端 | 页面、表单、草稿、可解释图表、可访问交互、同步状态 | 保留视觉系统与组件；业务仓储替换为 HTTP 客户端 |
| Node.js/TypeScript 业务后端 | 登录会话、RBAC、组织/学生作用域、命令、状态机、审计、通知 | 复用可迁移的 TS 领域纯函数；每项重新验证服务器边界 |
| PostgreSQL | 用户/组织/岗位/投递/面试/协议/去向/审核/通知等权威数据 | 设计迁移与约束；不直接信任浏览器提交的实体、分数或角色 |
| 私有文件存储 | 简历附件、证明、认证材料与文书 | 元数据与所有权在数据库；受控下载，不用公开 URL 替代鉴权 |
| 内部 DeepSeek adapter | 上游调用、响应校验、超时、费用与来源记录 | 可保留现有 Python adapter，由业务后端统一鉴权和代理 |
| 事件/任务层 | 提交后通知、定时提醒、重试 | 初期可用数据库 outbox + worker；需要时再引入消息中间件 |

部署路径和供应商尚未选定。可比较云主机自托管与托管数据库/身份服务，按预算、维护能力、数据所在地、学校网络条件决定；不默认购买产品、不注册账号、不把国内实际使用直接等同于海外 SaaS 可用性。

## 4. 在线数据与协作规则

### 4.1 身份和范围

- 学生仅访问本人数据；企业仅访问本组织岗位、授权申请及相应协作信息；辅导员仅访问获分配的学生；管理员按治理职责访问，不默认拥有无审计的所有隐私读取权。
- 注册不能自选管理员或辅导员。企业员工加入公司、学生名单导入、辅导员辖区调整均需授权与审计。
- 会话过期、禁用、退出、权限变更须由服务器生效；敏感后台账号采用加强验证。真实登录未完成前不得对公网开放演示角色切换。
- 路由守卫、隐藏按钮和本地权限函数不是服务端授权的替代品；查询、命令、导出、附件、订阅逐项校验。

### 4.2 事务与实时

- HTTP 承担写命令；服务端事务成功后产生事件，SSE 通知获授权客户端重新拉取相关资源。
- 事件携带最少必要信息，不能向所有角色广播完整简历、帮扶内容或附件位置。
- 继承 `commandId` 幂等和 `expectedRevision` 乐观并发思路，落到服务器事务、唯一约束和原子更新；限制重复投递和单生多份有效协议。
- 网络重试复用同一命令 ID；相同 ID 不同内容应拒绝。多实体写入成功/失败不可产生半完成业务事实。
- 事务 outbox 避免“已提交但通知丢失”；事件消费去重、断线游标/补查、权限变更撤销订阅一并设计。
- 冲突须让用户选择核对、合并或重新加载；后台更新不得静默覆盖未保存输入。网络未知时不显示已保存。
- 即时私聊是独立子系统，待确有需求再评估 WebSocket；不能因为要同步几项业务状态就先建设完整 IM。
- 正常网络下关键变更 1–2 秒可见可作为候选验收目标，需在约定设备、网络、负载下测量后定稿，不是现有性能承诺。

### 4.3 数据生命周期

- IndexedDB 仅作为可清理草稿/缓存，不再保存可自行裁决的业务事实；退出共享设备时提供安全清理。
- 演示种子与生产数据隔离；正式环境不暴露全库复位/角色模拟；数据迁移先备份、试迁移再切换。
- 使用服务器 UTC 时间，界面按业务时区显示；截止时间、届别和提醒规则可配置，不使用固定演示日期。
- 学生注销、毕业归档、投递快照、审计保留和依法删除的冲突需明确策略；不能照搬演示版“清除本人全部数据”而破坏组织合法记录。
- 上传校验扩展名、实际内容、大小、病毒风险与用途；下载每次鉴权；私有资料不进入访问日志或搜索引擎。

## 5. DeepSeek 接入的不可绕过边界

1. Key 仅在服务端环境/秘密管理服务配置；不放入 Vue、`VITE_*`、前端设置、仓库、导出包或日志，不在聊天中索取明文。
2. 服务器依据登录身份读取获授权的最小输入并脱敏，不接受前端任意声明用户/权限/数据快照。
3. 保留 LIVE / REPLAY / RULE 与真实 `origin`，失败时明确展示回退，不伪装成 DeepSeek 回答。
4. 按账号和全局限流、预算、并发；记录模块、模型、耗时、来源、失败原因及可获得的 usage。未知 usage 记未知，不编造成本。
5. 不让 AI 自行审批去向、自动拒绝候选人、覆盖分数或更改协议；生成建议由有权限的人确认。学生简历改写不得杜撰经历。
6. 用户提供可用 Key、允许费用且网络可达后，分别验连接、A1/A2/A3/A7 真实调用、结构与语义守卫、权限、超时/额度耗尽/停止/回退；题本和追问是否改成真实模型驱动须明确接线。
7. 若启用上游流式，验证真实增量、取消和背压，不把前端打字机动画当作上游流式证据。

## 6. 分期与放行依据

| 阶段 | 主要产物 | 放行依据 |
|---|---|---|
| O1 在线可信底座 | 身份/组织/范围、数据库/迁移、服务端命令、文件授权 | 两个独立学生/企业账户互不可越权；禁用立即生效；迁移可恢复 |
| O2 跨设备业务闭环 | 发岗、投递、邀约、协议、去向、审核、通知 | 电脑/手机独立会话完成一条真实持久业务链；重启后仍一致 |
| O3 实时与并发 | SSE、outbox、断线恢复、幂等、冲突交互 | 关键事件漏发可补查；重复请求不双写；并发签约不能双生效 |
| O4 真实智能能力 | 安全 DeepSeek 接线与业务效果样本 | 获授权的真实上游调用证据、来源展示、失败回退、输入权限与预算生效 |
| O5 可部署试用 | HTTPS、环境隔离、备份恢复、监控、压测、视觉回归 | 完成回滚/恢复演练；在明确负载下报告实际延迟/错误率；人工四角色走查 |

工作台补齐与上述阶段按依赖穿插进行，详见角色评估文档。先单院系/少量企业的封闭试点，再决定扩大规模；未经负载测量，不承诺并发人数、可用性等级或开发工期。
