# 全平台严格 DeepSeek API 设计规格

## 目标与批准记录

2026-11-15，用户批准在现有应用内统一改造所有 AI 功能，要求全局强制通过真实 DeepSeek API 服务生成，不得用固定内容、回放或规则结果代答。此规格把对话批准的方案落到可验收接口；尚未表示已实施。

配套外观规格：`2026-11-15-assistant-pet-design.md`。两项独立实施和验证，不互相替代。

## 范围与不可破坏约束

- 保留 Vue 3、TypeScript、Node、SQLite、现有登录、角色权限、CSRF、资源归属、revision 和业务确认。
- 不初始化或重置账号，不改写现有学生简历，不代用户投递；测试使用独立临时数据库和合成资料。兄弟稳定演示版目录不改动。
- 当前仓库无初始提交，文件全为未跟踪；不为满足工作流而创建初始提交，不清理、覆盖或回退已有文件。
- 已有项目外 Windows DPAPI 密钥仍只由服务端解密。密钥不得进入浏览器、源码、日志、数据库、测试证据或交付包。
- 所有面向用户的“AI生成/分析/建议/提问/评价/推荐”都必须有当次真实成功调用，不允许 LIVE 失败转 REPLAY/RULE，不允许没有密钥时返回预设业务答案。
- 权限校验、表单校验、统计、事实查询、可解释的规则分、PDF排版、动画状态和排序基础运算仍是程序逻辑，不冒称 AI，也不交给模型执行。
- 打开页面不自动付费；用户点击生成或开始面试才调用。历史读取明确为历史，不冒称重新生成。无自动付费重试。
- 保留 AI 授权关闭、取消、超时、共享额度限制；取消不承诺撤回已发给供应商的数据或消除已产生费用。

## 当前缺口与改造边界

| 入口 | 当前缺口 | 目标 |
| --- | --- | --- |
| 旧表达建议、A2辅助、A3解释、A7问数/帮扶 | `useBusinessAi` 可选择回放；orchestrator 在 LIVE 失败后找回放并生成规则内容 | 全部严格 LIVE，失败只返回错误，原文和业务记录不变 |
| 全局助手、独立简历优化、语音面试 | 已有真实 DeepSeek 链路，但可追溯成功凭据不统一 | 保持功能，补统一的最小调用凭据和失败检查 |
| “进行AI岗位匹配” | 目前主要计算规则依据，没有模型推荐调用 | 按真实候选资料调用模型生成推荐排序与理由；规则分单独标注 |
| 原文字面试 | 主流程为固定题库和本地评分 | 在线正式入口使用现有动态面试会话服务的文字模式；保留历史只读，不将旧分数改称AI分数 |
| OCR | 尚未接入 | 增加独立文档识别子页，真实OCR后展示逐页结果，人工核对，不自动覆盖简历 |
| 离线演示 | 可展示回放/规则 | 禁用 AI 生成入口，显示“需在线 DeepSeek 服务”；确定性业务演示仍可使用，静态范例不作为AI结果 |

## 架构与数据流

沿用同源后端 `/api/ai`（现有结构化 A1/A2/A3/A7）及 `/api/workbench`（对话、工具、动态面试）。不为统一调用强行合并已验证的业务接口；统一的是严格 LIVE 约束、密钥边界和成功凭据。

`用户动作 → 前端授权/取消 → 后端登录与权限校验 → 后端重建必要上下文 → 配额预留 → DeepSeek → 结构/安全/引用校验 → 权限复核 → 返回结果及调用凭据`

任一步失败：返回稳定错误码和重试提示，不调用回放，不构造替代答案，不把旧成功结果标记为本次成功。重新生成失败可以保留旧结果，但必须标为“上次结果，本次未完成”。

### 1. 旧调用链严格化

- `src/composables/useBusinessAi.ts`：在线状态不可用立即提示；不再导入回放记录给业务生成使用；不得以缺少ticket为由降级模式。
- `src/adapters/ai/orchestrator.ts`：LIVE失败必须向上传播；保留取消、输入脱敏、schema与semantic校验、revision/epoch及审计。不从 `findReplay` 或 `rulePayload` 补全失败的 LIVE。
- `src/services/ai-runtime.ts`：保留统一生命周期取消。业务入口不能用模式参数绕回预设答案。
- 离线演示与设计系统的静态示例和底层回放测试可以保留，必须与用户可执行AI生成入口隔离；正式服务不能加载它们作为答案。
- `AppShell` 等状态提示调整为 DeepSeek可用/不可用，不用“AI已开启”暗示当次调用成功。

### 2. 真实候选上的模型岗位推荐

- 真实岗位集合仍来自现有已审核站内岗位、公开索引及用户主动Search发现。模型不得新造岗位、招聘公司、链接或有效期。
- 先运行现有硬性条件过滤和资料覆盖标注，再向 DeepSeek 提交有限数量的候选（最多30条）和脱敏简历、求职意愿。超出部分仍列为“未参与本次AI推荐”，不能伪装为模型已分析。
- 模型只返回候选 `id`、推荐顺序、依据、差距、需核验信息；服务端拒绝未知ID、重复ID、超长输出、硬性排除却被推荐等无效结果。缺项按“未评价”处理，不补造AI理由。
- 原六维规则分保持独立、数值可核验；另列“AI推荐顺序/建议”，不把模型判断当录用概率，不把未知条件当已满足。
- `GET /matches` 只读上次结果；无结果时返回空状态，不在打开页面时付费或偷偷生成规则推荐。
- `POST /matches` 统一要求 `consent:true`，基础推荐必调模型；`discover:true` 先调 DeepSeek Search，再由模型基于返回链接/摘要分析。Search链接始终标记未经招聘资格核验。
- 现有单岗位 `/matches/analyze` 保留真实调用，返回调用凭据。结果绑定简历版本和意愿，变更后提示重新生成。

### 3. 动态文字与语音面试

- 正式 `/student/mock` 进入与语音面试相同的动态会话服务，默认文字回答；语音入口保留默认语音模式。
- 复用 `/sessions`、`/sessions/:id`：首题、后续问题、引用评价均由 DeepSeek 实时生成；文字输入不需要ASR/TTS，也不应额外调用这些工具。
- 无有效评价时显示“评价未完成”，不生成0分或本地替代分。汇总只计算已取得有效模型评价的轮次，并说明计算口径。
- 回答先保存再等待下一题和评分。取消、超时、余额不足保留已提交回答；下一题失败允许用户主动重试或结束。
- 旧规则练习记录只读，清楚显示“旧规则练习”；不删除、不迁改为AI会话，不让新的正式开始按钮走旧固定题库。

### 4. OCR文档识别

- 新增 `/student/resume/import` 子页，仅approved学生可用；简历主页面和优化页面提供入口。
- 支持PDF、PNG、JPEG，应用级每次1个文件、最大2MiB；PDF最多20页，后端在外发前验证。使用实际文件签名，不只信任扩展名或浏览器MIME。
- `POST /api/workbench/documents/ocr` 使用原始文件字节、明确文件名和 `X-AI-Consent:true`；后端重建 `multipart/form-data`，仅发送 `file` 与 `purpose:text_recognition` 到官方 `/v1/tools/ocr`。
- 外发提示明确：文件内容包括姓名、联系方式、证件信息时会一并发给DeepSeek；图片不能被文本脱敏函数可靠匿名化。识别不是证书真实性认证。
- OCR允许官方最长180秒识别窗口，应用超时稍长于官方窗口；不得继承聊天60秒超时后宣称识别已取消。明确提示文件接收后供应商可能继续执行并计费。
- 即便HTTP200也检查 `error`、`pages`、页码、`page_count` 与 `finish_reason`；`length`显示该页不完整。错误不以本地提取结果代替OCR成功。
- 展示逐页原始识别文本和截断提示，可复制；未确认内容不自动写入正式简历。此次不做自动身份核验、自动填表或自动更改证书字段。
- 输入文件和识别正文默认不存平台磁盘或业务库；仅页面暂存，离页清除。审计不记录原文。

### 5. 调用来源与审计

- 服务端每次真实尝试记录无正文的最小凭据：本地traceId、操作者内部ID、模块/工具、模型、时间、成功/失败、稳定错误码、供应商requestId（有则保存）、usage（有则保存）。不伪造供应商未返回的ID或token数。
- 成功凭据仅在实际上游成功并通过校验后产生；审计不可由客户端传入成功标志。
- UI生成结果可查看“DeepSeek实时生成”、生成时间与本地请求标识；历史标明原生成时间。音频二进制响应可用安全响应头带traceId。
- 审计与配额计数不能泄露自由文本、姓名、邮箱、音频、密钥或完整上游错误正文。权限不因审计扩张。
- 不作“完整合规审计”承诺；目的是验证调用来源和排查失败。

## 验收要求

1. 无密钥、禁用、401/402/429、超时、断流、畸形JSON、语义校验失败均不能返回回放或规则代答；测试断言不会触达回退提供者。
2. 所有可见AI生成按钮均映射到真实DeepSeek后端路径；完整清单覆盖学生、企业、辅导员、管理员及全局助手，不为原本没有AI生成的页面强加付费功能。
3. 测试模型推荐只使用真实候选ID，规则分不变，候选资料注入无效，跨用户和失效revision被拒绝；无岗位时显示空状态而非编岗位。
4. 动态文字与语音使用同一真实模型会话服务；旧规则记录和新AI记录标签分离；失败不生成替代分。
5. OCR验证文件、大小、PDF页数、授权、HTTP200error、截断、取消与无落盘；不能越权识别他人附件。
6. 隔离库使用合成供应商做自动化错误/权限/UI测试，明确不作为真实API证据；另用合成材料、有限次数执行真实DeepSeek烟测，记录调用凭据与结果，不外发真实学生材料。
7. 本轮重新执行typecheck、lint、build、单元及受影响E2E；不能引用上一轮测试数字宣称本轮完成。保留实际库一致性检查与备份。
8. 交付记录明确通过项、未通过项、真实API调用次数和未验收的物理设备体验；不把“可用配置”当“所有功能真实调用已通过”。
