# 路鸣职引 CareerPilot 全站 UI/UX 升级设计 v0.1

日期：2026-11-16。状态：具体设计首稿，待用户评审；不是实现完成声明。

## 1. 已确认目标与边界

保留现有全部功能、业务、数据与技术能力，升级全角色、全页面、全窗口及适用状态的视觉与交互呈现。主技术栈保持 Vue 3、TypeScript、Router、Pinia、自研组件/CSS、ECharts、在线 Node/SQLite 与离线 Dexie。不迁移 React，不搬入整套后台模板，不引入第二套路由/状态管理。

此次输出为设计文档、静态可编辑 SVG 设计稿、候选令牌、覆盖清单与保护基线。SVG 中的虚构姓名、数字和状态仅为排版样例，均不是正式数据、运行截图或实际服务状态。不发起 AI 请求，不执行来源同步，不初始化数据库，不改账号或凭据。真实运行数据不进入云端设计。

设计包目录：`docs/design/ui-refresh-2026-11-16/`。现有源码与配置的 SHA-256 记录在 `protected-baseline.json`，涵盖 185 个文件、71 个 Vue script 区块；不包含密钥、真实库或密码内容。该文件仅用于变化核对，不是备份、业务正确性证明或已通过测试的证明。

## 2. 设计方向：灯塔·清晰工作台

保留现有路鸣职引文字标识与徽记、品牌蓝及 AI 辅助紫。视觉语言：明确层级、可读中文、低噪声表面、适度留白、精确对齐、轻量反馈。门户比后台舒展，编辑界面比展示界面专注，分析界面比普通卡片更强调数据可读性。

选定路线为设计系统演进、页面族升级、逐屏迁移。没有选择仅全局换肤（不能解决布局和状态问题），也没有选择整套模板替换（框架与行为回归成本过高）。

业务页使用任务型标题，如“就业质量驾驶舱”“简历工作台”“候选人流程”；品牌宣传语仅作为门户主标题或短辅助说明，避免每页重复大幅宣传横幅。业务页的主要操作放在标题同一行或紧随其后，窄屏换行，不能裁掉操作。

## 3. 业务与 AI 保护契约

### 3.1 不变量

- 所有现有角色、权限、路由访问限制、数据范围、前后端校验、必要警告、可执行操作、命令字段与结果保持一致。
- 数据结构、版本号、修订冲突、命令幂等、审计记录、投递简历快照、附件权限、保存/导出语义、在线/离线区别保持一致。
- 不删功能、不加隐性提交、不改变确认门槛，不用视觉进度结束事件推进状态。
- 真实 API 允许合理非确定性；不以改造前后模型输出逐字相同作为验收。比较调用契约、触发条件、结果类型与业务处理，而不是随机文本。

### 3.2 AI 专项保护

保护范围包括 `server/ai.ts`、`server/workbench/`、`gateway/app/`、`src/adapters/ai/`、`src/adapters/repository/http.ts`、`src/services/ai-*`、`src/services/interview-*`、`src/services/workbench-*`、`src/domain/ai-guard/`、`src/contracts/`、`src/composables/useBusinessAi.ts`、相关 stores 和调用页面的 script 区块。

保持模型配置、提示词、参数、上下文组织、脱敏/整文件外发边界、额度、确认票据、状态流转、取消、超时、错误处理、已有重试方式、输出校验及来源记录不变。CSS/模板改动也须检查事件绑定与条件判断，不能只检查 script 哈希。

首版迁移原则上不改业务 script；确需调整前端展示结构或提取纯展示逻辑时，列出差异并证明不改变事件、参数、生命周期与结果。保护路径有任何非展示需求的变更，先报告并取得单独批准。

动效不得增加生成调用，不得重复挂载活动 AI 页面。保持 Router 导航时现有取消逻辑，不对业务 RouterView 添加变动 key 或 out-in 过渡造成重复挂载，不擅自用 KeepAlive 改变清理时机。ResizeObserver、IntersectionObserver、滚动和动画回调只改变展示，不触发业务命令或 AI 请求。

“已允许调用”表示现有默认授权开关；不是已连接或正在生成。维持 `aiConsent` 现有默认值及关闭行为，不悄悄新增每次调用强制确认，也不取消现有某些场景的确认。`/api/ai/status` 查询与模型生成分开计数，不把正常状态读取误判为付费生成。

OCR 整个文件外发，不可宣传为已可靠文本脱敏；语音自动播放/收音和自然轮换的既有启用条件、时间与暂停行为不改变。AI 来源披露保留。服务失败不得使用回放/规则代答；旧规则练习独立标识，不能混成新 AI 面试。

### 3.3 验证路径

记录主动操作到事件处理器、请求、业务结果的映射；以隔离数据、可控响应验证没有额外生成、重复提交、隐性重试、过期结果回写。关闭授权、切换路由、取消、网络失败、流式中断、结果校验失败、IME 输入、麦克风失败均须覆盖。真实 DeepSeek 检查另行费用确认，不在设计阶段调用。

## 4. 视觉基础

### 4.1 颜色与主题

保留生产令牌名称和现有安全配色作为 v0.1 颜色基线，首轮不为“全新”任意换色。可在设计评审后修订。候选扩展为统一间距、字号、层级、图表语义色与窗口尺寸，记录在 `design-tokens.proposed.json`。不直接覆盖 `src/styles/tokens.css`。

浅色底 `#F6F8FC`、表面 `#FFFFFF`、主文字 `#16233A`、次文字 `#5A6782`、品牌 `#2F55C8`；深色底 `#0E1421`、表面 `#161F31`、次级表面 `#1E2A40`、主文字 `#EEF3FC`、次文字 `#A7B4CC`、品牌文字 `#91A9FF`。AI 紫只标识 AI 能力/来源，不能把不可用状态做成“成功绿”。危险操作使用对应 danger 文本与底色，状态同时提供文字，不只依赖颜色。

正文普通文字目标 4.5:1，大字号按适用标准至少 3:1；必要控件边界、焦点与图形识别目标 3:1。装饰分隔线与必要控件边界区分；不能要求所有装饰线均达到 3:1。令牌合格不代表实际叠加、透明度和图表内部颜色已合格，需要运行态复核。

### 4.2 中文字体与排版

沿用产品字体栈 PingFang SC / Microsoft YaHei / Noto Sans SC / system-ui，不默认替换为 Inter，不为设计稿额外下载大字体。数字尽可能使用等宽数字特性；代码/请求标识使用 mono。正文 14/22，编辑字段与窄屏输入 16/24，辅助说明 13/20，图表标签至少 12/18，重要风险说明不得因辅助样式缩成难读的小字。

门户主标题桌面 56/68、窄屏 34/44；业务页 H1 桌面 28/38、窄屏 24/34；H2 20/28；H3 16/24。字重优先 400/600，不整页粗体。正文不使用过大字距，英文眉题允许轻微字距，不以全大写英文替代中文。

### 4.3 空间与密度

4px 基础尺度：4、8、12、16、20、24、32、40、48、64。窗口留边和业务内容间距根据宽度切换。桌面侧栏 224、顶部 64；业务主区桌面 32、平板 24、手机 16px 内边距。常规内容最大 1440，门户最大 1296，编辑主列最低约 480；按实际容器选择布局，不强撑列数。

控件圆角 10、卡片 14、窗口 20，与现有语义兼容。表格用分隔与对齐建立层次，不每个单元格都加阴影。卡片边框稳定，阴影主要用于浮层和轻量悬停。默认控件高 44，紧凑桌面可 36；手机主要触点目标至少 44×44，这是设计目标而非声称所有 WCAG 条款强制 44。

### 4.4 响应式

完整检查 375/390、768、1024、1280、1440、1920px；另检查 320 CSS px 等效重排与 200% 缩放。1024 以下侧栏切为已有移动导航，不新加第二套底部业务导航。密集宽表允许在有清晰提示的局部容器横滚，页面整体不得横向溢出。

表单桌面两列、手机单列；标签和错误靠近字段。长标题换行，不截掉唯一身份信息。sticky 操作区必须为正文保留空间、遵守软键盘与安全区域，不能遮盖底部按钮。小屏拆栏只改变布局，不重新挂载编辑/录音/生成任务。

## 5. 组件与状态设计

### 5.1 保留与升级

沿用 AppButton primary/secondary/ghost/danger、sm/md/lg 与 loading/disabled/type 语义；保留 `disabled || loading` 和 `aria-busy`。状态：default、hover、pressed、focus-visible、disabled、loading。尺寸与状态分表展示，避免把每个图标扩成变体。

沿用 AppInput、AppSelect、AppTag、AppCard、AppSkeleton、AppToast、BrandMark、EntityMark 和 AppIcon。输入保持原 model/update 事件、名称、限制、原生语义与输入法行为。自定义选择器无必要不替换原生 select。

AppOverlay 为 Modal/Drawer 统一底座，保留 Teleport、焦点限制/恢复、Esc 与滚动锁；按现有调用方的 busy 关闭策略处理，不能全局统一成一律可关或一律不可关。设计建议增加纯展示尺寸/描述/区域样式能力，不改 close 事件语义。

建议新增或规范化的纯展示组合：PageHeading、ActionBar、FilterBar、FieldGroup、StatusBanner、EmptyState、DetailPanel、ChartPanel、DataTableFrame、AiStatusSummary、DocumentFrame。仅抽取稳定重复模式，不要求每个 section 都组件化。

### 5.2 窗口

确认弹窗宽 480，常规表单 640，宽对照 960；全受视口限制。桌面遮罩保留父页面上下文，头部与底部操作区稳定，正文单独可滚动。手机最大 `100dvh - 32px`，内容过长可使用近全屏呈现，保留标题与关闭/返回入口。

图纸采用现有“驳回本次材料”为窗口样例：原因最多 300 字、至少 5 个字，危险确认样式、取消次操作，保持现有提交与确认要求。不要在准入岗位审核中误套此处 5 字规则（其原有规则不同）。

浏览器原生 confirm 属于需单独设计/验证的例外：语音结束/删除、优化重生成/保存/版本恢复/离开、题库练习、助手删除等均登记。若后续换成应用确认窗，必须逐个保留触发条件、确认/取消分支、阻断时机和业务结果；不能在第一次换肤时批量替换同步 confirm，先专项审批与测试。

### 5.3 状态反馈

loading 保持布局，不先闪空态；empty 区分“尚无数据”和“筛选无结果”；error 保留用户输入与可恢复操作；saving 禁止重复提交；conflict 保留现有重新读取/丢弃语义，不能自动覆盖；权限不足不展示越权数据；长等待使用真实阶段与取消提示，不倒计时承诺完成。

## 6. 关键页面具体结构

### 6.1 就业质量驾驶舱（第一优先）

标题区：当前辖区、届别、统计时点、导出当前视图。保留四项 KPI 及原口径。

桌面采用宽度优先的两列图表（每面板可用宽至少约 400），不是三窄图再挤入 330px 风险栏。第一行去向结构+投递转化；第二行八周趋势+慢就业预警；专业×行业热力图独占下一行；自然语言问数保留在下方。窄容器全部单列。

环图图例使用主题文本色并预留完整行高；漏斗缩小图形占宽、在图表面板右侧预留完整标签区，标签不得裁切；趋势保留真实缺失周，不补造数据；热力图说明单位、零值与缺失值，保持真实聚合。保留各图原有 summary，不以 tooltip 作为唯一信息来源。零预警是成功空态而非异常，不添加虚构学生。

自然语言问数保持“本地问数”和“生成问数解读”两种动作与数据来源区别。风险帮扶建议、记录闭环、复查、关闭按原状态出现。连接提示不额外增加按钮禁用条件，服务检查与错误处理沿用现有生成流程；简历稿中的禁用示例由原有 dirty 条件决定，不以服务标签新增业务门槛。打印/导出仍包含所有原有数据与口径。

### 6.2 简历工作台（编辑优先）

标题+已保存/未保存状态；主要动作“保存新版本”，预览导出、AI优化、OCR、版本对比、打印等原入口全部保留，通过第二行工具栏自然换行，不藏入无法发现的菜单。

宽屏段落导航 152，编辑区自适应最低约 480，诊断/建议 288；空间不足先把段落导航改为横向分组，再把辅助区移到编辑内容之后。手机标题、保存区、段落导航、基本信息/教育/实习/项目/技能/证书依次呈现；体检摘要可短行展示，完整诊断不抢占编辑前多屏空间。

保留所有字段、附件、版本、草稿恢复、冲突处理与保存后重新计算。体检分是最近保存版本的本地完整度，不是 AI 分或录用评价。建议区保持参考岗位、策略、保留语气、主动生成、停止、原文/建议/证据与逐条采纳限制。优化草稿不自动保存，OCR 不自动填入正式简历。

### 6.3 公共门户与岗位发现

保留主文案“让下一步，更有方向。”、现用校园图（campus-ai.jpg 及原有失败回退）、搜索、岗位列表、全部机会、五项国家平台就业服务和三项求职准备入口；保留学生注册、企业入驻、学校工作台及页脚入口。首屏减少无效间隔，搜索与主要行动明显；岗位行按名称/企业、地域/学历、薪资、来源/类型稳定对齐，手机按阅读顺序重排，不杜撰认证、推荐人数或就业率。静态稿显示三条虚构岗位仅供排版，实际数据条数与分页读取方式不变。

使用现有图片和 BrandMark，动态图形只在背景轻量呈现。无图/坏图有有意义回退。来源标识和校外跳转提示不能因美化消失。

### 6.4 企业招聘与候选人

overview/jobs/candidates/agreements 独立登记。概览缩短宣传区，使招聘管线和待处理操作靠前。候选人采用列表/详情结构，搜索、阶段、排序保持原语义；窄屏上下结构或清晰返回，不丢失选中项。

详情突出投递快照、岗位、阶段、完整简历入口、证据、日程、反馈、意向与协议。企业仅看已有授权范围，不新增跨岗位信息。岗位编辑、面试安排/改期/取消、结果、结束流程、意向签发/撤销与企业资料窗口全部单独验收。

### 6.5 辅导员名册、审核与帮扶

保留检索、专业/届别/审核状态、待审与名册切换、学生详情、材料附件、来源、历史记录和现有命令。学生选择状态可见且不会只依赖底色。主操作紧邻证据但不遮盖附件。

审核通过与驳回保持现有触发；不能为了统一窗口擅自添加/删掉二次确认。驳回和撤销清晰区别。帮扶保留创建、复查、结案、重开和确认勾选。

### 6.6 管理治理

控制台账号管理、来源、实体计数、版本与脱敏审计重排为一致密度的区块。不要显示管理员原本无权看的简历或附件。账号审核、同事邀请、准入、岗位审核、辖区交接、机会同步/核对/发布均保留原字段与规则。危险演示复位独立区域，不与普通刷新共用样式。

### 6.7 AI 面试与助手

文字/语音面试模式保持独立标识；同一会话的已有模式切换、语音自动开关、自然轮换、转写核对、暂停、重新读取、提交、下一题、结束、报告、历史删除全部保留。主要问题和回答区优先，成本/隐私说明可分段但关键外发范围和调用提示始终清楚。现有 6 轮上限、转写 2 秒提交等业务参数不因动效改变。

助手只解释与导航，不暗示能自动提交。保留历史、新对话、联网补充资料、来源、IME 输入和 Enter/Shift+Enter 规则。输出滚动只在用户位于底部时跟随，查看历史时不抢滚动，提供回到最新；不改变流式数据缓冲/安全审核逻辑。

## 7. 动效规范

即时反馈 120ms、状态切换 180–200ms、面板 240–280ms；滚动进入 240ms、位移最多 8px、错峰间隔 40ms、总序列最多约 400ms。交互立即可用，内容默认可见，JS/观察器失败不能留下 opacity:0 的正文。

优先 CSS transform/opacity，避免全站 transition:all、重排大动画、持续高开销滤镜和全屏 WebGL。门户低幅背景可以持续，但要有暂停/减少动态模式且离屏停止。业务表格不循环闪烁，不自动重排，不自动纵向滚动。

图表首次进入短过渡，不反复播放；KPI 保留最终数值与可读文本，不从 0 滚到业务值造成误认。波形只绑定真实录音电平，未录音不假装收音。没有可测进度时用阶段文字/不定进度，不展示假百分比。

尊重 prefers-reduced-motion，取消位移/持续装饰、保留必要静态状态。每个动态展示均有无动效等价信息。自动滚动信息必须可暂停、手动访问；不劫持滚轮或强制整屏翻页。

现有宠物沿用原角色、动作、长按拖动、键盘移动、大小、睡眠、暂停、漫游与许可说明。设计稿提出侧栏底部专属停靠区以减少遮挡；这是待确认的呈现建议，不自动改变现有位置/漫游设置。移动端需避开保存栏与软键盘，禁止在用户拖动后持续抢回位置。不得以宠物动效触发 AI。
