# 第五阶段：适量岗位资源与公共门户设计

北京时间2026-11-14。范围：公开岗位发现、受控国家平台链接索引、公共首页及现有招聘链路的衔接。本文件是设计，不是开发完成或生产放行证明。

## 1. 决策来源与状态

- 继承 `../../stage-three-traceability.md` 所列八段讨论，以及公共首页、在线升级、角色工作台和第四阶段账号服务的已完成成果，不重新建设账号底座。
- 上轮提出“统一招聘门户 + 受控公开采集 + 区分站内办理与原站申请”。本轮用户要求“有序稳定推进，岗位、招聘相关的内容不要从平台爬取过多过量，适量适当科学合理即可”，据此继续细化该方案，缩小采集范围。
- 采用品牌叙事与轻量就业门户结合的方案。仅扩充外链列表不能解决发现与登录衔接；全量镜像增加过时、转载和维护风险，均不采用。
- 当前状态：用户已于2026-11-14确认实施并要求本阶段收官测试。按顺序实施计划推进，完成事实以第五阶段证据为准。

## 2. 目标与边界

1. 访客不登录即可搜索、筛选和查看可公开岗位；首页既有品牌识别，也有清晰、适量、可用的内容。
2. 站内岗位保留已审核企业、岗位审批、实际投递、邀约、Offer、协议和去向的服务器权威链路。
3. 国家平台岗位是附来源的外部机会，不是本站企业发岗，也不创建同名企业账号、招聘认证、候选人或投递事实。
4. 正常在线页面不展示无关的“虚构”“演示”字样，不删除来源、隐私、AI回退、资格限制与申请方式等必要告知。离线教学环境的真实性披露继续保留。
5. 本阶段交付为本机服务候选版。无授权公网目标，不购买服务、不开放公网、不承诺生产容量。PostgreSQL、多实例事件、TLS、真实设备及原P2/P3仍按既有路线单独放行。

## 3. 适量采集的硬边界

| 项目 | 首期规则 |
| --- | --- |
| 内容目标 | 首次目标20条岗位，单次解析与暂存最多30条，不为凑足数量追加翻页；不足20条按实际结果保留 |
| 请求预算 | 每次最多6个HTTP请求，包含列表、人工抽样详情与重定向；默认1次列表请求，详情抽样最多3条，剩余额度不用来自动补抓 |
| 请求节奏 | 单并发，相邻请求至少间隔2秒；每个响应10秒超时、解压后正文最多1MiB；无自动重试、无并发抓取 |
| 更新频率 | 仅管理员手动启动或显式本机维护命令；任意连续24小时最多一次实际网络同步，失败也计入；没有定时任务、后台轮询或自动扩量 |
| 覆盖范围 | 只采公开职位的最小字段和标准详情链接；不做全站、全国分区轮巡、企业名录或历史回溯 |
| 停止条件 | 登录要求、验证码、403、429、异常重定向、超限、超时、结构变化立即停止本轮，保留原有已发布数据；不绕过访问限制 |
| 数据权限 | 公开可访问不代表批量转载许可。当前仅做有限事实字段与链接索引，不镜像完整岗位正文，不抓联系方式、联系人、简历、证照、用户信息、企业标识图片 |

服务器固定允许的列表及详情路径，不接受任意URL、代理地址、客户端自选请求头或抓取脚本。重定向不自动跟随到其他地址；需核对后显式放行且仍计入预算。一次网络同步失败不能通过另一个入口绕过24小时限制。没有网络采集权限的学生、企业及辅导员不能触发请求。

2026-11-14的只读研究确认公开列表可读取，但没有取得批量转载授权；robots地址返回404样式HTML，不视为许可。若实施时发现站方明确禁止相应索引，停止采集，继续保留人工核对外链及原站服务入口，并记录原因。

## 4. 数据模型、来源与治理

### 4.1 独立外部机会

外部机会与既有 `Job`、`Company` 分开存储，以 `ncss:<sourceJobId>` 为稳定键；站内公开机会使用 `local:<jobId>`，避免混淆与ID碰撞。

允许字段：岗位名称、企业名称、原文地域、学历、专业要求、招聘类型、薪资原文及经确认口径的数值、招聘人数、行业、企业性质/规模、来源平台、底层信息来源、标准详情URL、原站发布时间、原站更新时间、采集时间、截止时间、核对状态、审核状态、revision。缺失值为null或空列表，不猜测截止、届别、全国地域映射或薪资。

原站发布和更新日期分别保存，不能用更新日期推定面向新一届毕业生或仍在招聘。薪资字段单位和边界在解析测试及详情抽样确认后才能格式化；不能确认则显示原站文本或“原站查看”。聚合自智联招聘等渠道时，同时保留“国家大学生就业服务平台”和底层来源，不能冒充直接企业发布。

不导入HTML、脚本、远程图片，不使用 `v-html` 渲染抓取内容。只保存白名单事实字段与短资格提示，不保留整页原文或未经裁剪的响应日志。原站声明的资格限制优先；抽样发现的“更新较新但仅面向往届”须显示简明提醒，其他岗位不声称资格已经逐条核实。

### 4.2 暂存、审核、发布

数据流：手动同步 → 校验/规范化/去重 → 暂存预览差异 → 管理员审核发布 → 公共查询及学生入口。

- 新数据不因采集成功自动公开；管理员看新增/修改/无变化/拒收数量、字段差异、核对日期及原站入口。
- 以来源ID/标准URL去重，重复同步不新增岗位。输入记录超过上限拒绝，不悄悄截断后宣称全部成功。
- 已发布内容更新先形成候选版本，原版仍可读；审核通过后事务替换。审核拒绝、冲突或网络失败不清空旧版。
- 发布/下架有角色校验、expectedRevision、commandId幂等和纯业务摘要审计；重复提交不双写，相同命令ID不同内容拒绝。
- 管理员可带原因下架。采集窗口未再次出现某岗位不能推断已关闭；已知截止已过的从默认在招发现列表移出。
- 采集超过7天提示“信息待更新”；超过30天不再进入新的默认发现结果，但本人既有收藏/记录可见并提示核对。不声称待更新岗位已停止招聘。
- 无截止信息时详情仅提示“招聘状态与申请条件请以原站为准”，不把未知状态标为已核验有效。
- 已有静态3岗位索引经校验后至多迁移一次为待审条目；静态服务链接与岗位分开，页面不再重复出现两份岗位区块。

### 4.3 持久化与恢复

新增外部机会、候选版本/同步批次、个人记录及操作回执使用独立SQLite表与索引，迁移单独递增schema版本。不修改旧实体的业务语义，不向离线种子写真实岗位。

升级前备份当前服务库；先用隔离副本验证迁移、回滚方案和备份恢复。回滚用迁移前快照与完整旧版本，不能用旧程序打开新schema。外部索引、审核状态、收藏记录和同步预算均须跨重启/恢复保留；恢复继承撤销旧会话规则。

## 5. 公共首页与岗位发现

### 5.1 首页结构

1. 简洁导航：品牌、岗位机会、就业服务、招聘专场入口、注册/登录；已登录显示进入本人工作台。手机保留可用导航，不把全部入口隐藏。
2. 品牌首屏：保留“路鸣职引 CareerPilot”与校园到职业的视觉连续性；主标题沿用“让下一步，更有方向。”。岗位搜索成为明确主要行动，次行动通向求职准备。
3. 岗位发现：统一展示最多6条有效公开机会，明确站内/原站办理；查看全部进入公开列表。首次站内无岗位时不另放空列表挤占首屏。
4. 招聘与就业服务：有限的专场招聘、实习、就业指导、政策和风险提醒入口。只有原站入口时写“前往国家平台”，不提供本站报名/签到或编造活动日期。
5. 求职准备：简历完善、岗位发现、面试练习各有真实可用目的地，受保护操作经登录返回；不宣传尚未接通的真实AI能力。
6. 角色服务与页尾：学生、企业、学校支持与平台管理的适当入口，精简价值说明和必要帮助，不展示虚假合作院校、规模或成功率。

以开放列表、留白、浅色区与一段深色角色服务形成节奏，不把全页改成等大卡片墙。桌面内容宽约1200–1320px，手机页边距20px；大标题约40–60px，主要正文16–18px，元信息14px左右。删除重复图片注释、冗长区块解释和重复来源段落；必要来源集中于行内标识和详情。

现有本地校园图作为已可用素材。新图仅在确有视觉收益且完成默认 `skill-1k` 流程后使用；失败标记“稍后重试”，保留素材接口与本地图回退，继续功能实施，不自动付费重试或切换供应商。页面不依赖图片生成服务才能使用。

### 5.2 公开列表与详情

- 新增公共列表与详情路由，不要求先选身份。站内/外部机会共用可扫描字段及明确的办理标识，但查询模型不混为同一业务实体。
- 支持岗位/企业/专业关键词、地域、学历、招聘类型、来源筛选，最近更新排序与分页；默认每页10、上限30。未知字段可识别，不用缺省值冒充不限。
- 搜索参数在URL中保留，回车提交、清空筛选、空态、加载、失败重试、详情返回保留条件；前端过滤不能代替服务端分页和公开字段投影。
- 公共API只返回公开岗位和被引用的企业名称/字典，不再泄露无公开岗位的全量企业名称。公司私有联系人、候选、附件、审计和未审核岗位不进入响应。
- 详情呈现核心要求、来源/底层来源、更新时间、截止或未知状态、申请方式。站内内容来自审核后投影；外部无完整正文时明确“完整要求请查看原站”，不生成替代JD。
- 登录回跳限制在站内合法路径且重新鉴权，不能自动收藏、投递或记录。待审账号可浏览公开内容，但收藏、记录和工作台业务仍由服务端拒绝；调整路由守卫时一并测试。
- 原 `/api/public/jobs` 在迁移期间保持兼容，公开字段收紧；统一查询使用独立公开机会接口，避免破坏既有页面与测试。

## 6. 全链条角色衔接

### 6.1 学生

学生“岗位匹配”与公共机会入口复用外部查询/详情，不再嵌一块独立的3条静态外链。站内岗位沿用现有六维匹配；外部字段不足时仅显示可核对的条件，不生成虚假百分比匹配。

外部收藏/求职记录仅本人可读写、跨设备持久化。可明确记录“关注、已自行投递、面试中、收到意向、已结束”，标明“本人记录”，保存本人选择的日期和少量备注。点击原站或收藏不创建“已投递”，状态变化必须本人显式确认；不保存外站登录凭据、不替本人向外站投递、不导入外站私信。

外部记录不进入站内企业候选、Offer或协议，也不计为站内已投递/就业落实。已有站外就业去向入口可以继续由学生手动填报单位并上传证明，辅导员按原流程审核；不从浏览/自报Offer自动填成已审核去向。删除或下架机会不级联删除本人历史记录。

### 6.2 企业、辅导员、管理员

- 企业沿用本组织发岗→审核→学生授权投递→邀约→录用意向→双边协议；不得修改外部岗位或查看其收藏者，不因名称相同取得外部雇主身份。
- 辅导员沿用获分配学生的帮扶与去向审核；本阶段不额外授予读取学生私人外部求职备注的权限，不把自报记录混入就业统计。
- 管理员新增来源治理入口，负责同步预览、审核、核对、下架和批次结果；不获取学生私有求职备注，不把内容审核等同于现实招聘真实性认证。

### 6.3 同步与并发

写操作通过服务器事务提交，复用已授权用户的SSE变更信号；另一独立学生会话应重新读取本人收藏/记录，管理员审核也触发有权限页面更新。不广播原始备注或候选数据。

公共页使用内容版本与可控刷新机制，刷新/回到页面时重新校验；不为本阶段扩建匿名SSE或制造浏览器轮询风暴。公开列表不承诺毫秒级同步。修改同一记录的并发冲突保留输入并提示重新核对，不静默覆盖。

## 7. 错误处理与实施节奏

- 顺序执行，不派发并行代理。先模型/解析与隔离测试，再公开查询/治理，再首页和学生衔接，最后全链回归、切换与文档。
- 非关键素材/外站可用性问题登记后继续，保留上次有效内容；权限、泄密、数据损坏与错误业务事实须先修复，不能延期带入交付。
- 无授权、无有效岗位、未知字段均提供诚实空态，不用演示数据在在线服务默默填充。
- 在隔离端口/数据库和独立构建目录验证，不在实际4174服务运行时覆盖其dist。不重置 `server-data/service.sqlite`，不将私有初始密码写入日志、截图、包或文档。
- 本仓库develop没有HEAD；保存文档和变更清单，不替用户创建整个项目的初始提交，不宣称已经commit、push或独立审查。

## 9. 自查结论与下一关口

- 目标20条、硬上限30条与网络预算6次属于不同维度，不以多轮采集绕过限制。
- 有限公开索引与转载授权分开；详情链接与实际投递分开；个人自报进展与企业文书/审核统计分开。
- 首页、学生、管理员改进共用机会模型；企业和辅导员继承既有权限，不增设无关子系统。
- 同步仅手动，没有调度任务；图片失败可延期，安全问题不可延期；没有把本机交付等同公网成熟生产。
- 下一步请用户审阅本文件。确认后按 `superpowers:writing-plans` 写出测试驱动的顺序实施计划，再用 `superpowers:executing-plans` 执行。
