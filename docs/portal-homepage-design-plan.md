## 1. 必须继承的需求与定位

- 打开项目主网址，先看到一个面向所有访客的共同首页，而不是直接进入“选择演示角色”或某一角色仪表盘。
- 对标成熟 Web 应用的公共门户：有明确品牌、服务价值、主要行动、真实内容入口、受众分流与可信信息。
- 画面有吸引力、原创构思和细节质量，且紧扣“毕业生就业管理与智能服务”，不变成无关的炫技展示。
- 与现有“路鸣职引 CareerPilot / 灯塔 Lighthouse Design”及四角色升级方向一脉相承，不重新命名、不随意替换徽记或技术栈。
- 保持全站美观不单调；首页负责吸引、理解、发现服务，登录负责验证身份，工作台负责办理，不将三者挤成一个页面。
- 与 `online-upgrade-strategy.md`、`role-workspace-assessment.md` 共同作为后续开发输入；不覆盖冻结基线和稳定演示版。

这是项目内的持久设计记录，不表示模型具有永久跨会话记忆；后续开发应主动读取本文件。本文的候选文案、尺寸和功能顺序是设计建议，不冒充用户已逐项批准的最终界面。

## 2. 当前入口与需要改变的关系

源码 `src/router/index.ts` 目前将 `/` 重定向到 `/login`；`LoginView.vue` 是品牌双区 + 四角色演示选择。当前没有独立公共门户。角色主页与公共首页必须分开。

| 页面层 | 职责 | 后续处理 |
|---|---|---|
| 公共首页 `/` | 介绍价值、浏览公开机会/服务、引导下一步 | 新增公开页面与公共布局，不套角色后台侧栏 |
| 登录 `/login` | 身份验证和受控进入 | 保留已有品牌构图，在线版接真实认证；“四角色任选”仅在隔离演示环境保留 |
| 公开列表/详情 | 展示已批准公开的岗位、活动、指导内容 | 按上线范围逐步启用；不借公开路由读取整份内部业务快照 |
| 角色工作台 | 个人待办、申请、招聘、审核、帮扶和治理 | 保留现有路由边界；按前轮评估补齐功能 |

访问主网址时，无论是否登录，都可看到共同首页；已登录只将“登录平台”改为“进入工作台”，不强制把访客从首页弹走。收藏、投递、预约等受保护动作经登录后回到原目标；不能替用户自动提交。真实多角色账号的可用角色由服务器授予，选择界面只选择已获授权的工作空间。

当前 hash 路由可先保留，浏览器入口仍是同一站点根地址。未来有搜索引擎收录需求时再比较预渲染/SSR 与 history 路由，配套服务器回退和真实 404；不为一个门户页立即重写 Vue 全站。注意当前已有根重定向和根 AppShell，实施时应整理公共/受保护路由关系，避免新旧根路径匹配冲突。

### 3.1 三种构成路线

- **推荐：品牌叙事 + 轻量公共服务门户**。首屏先建立价值和记忆点，第二屏提供机会与服务，再用真实业务示例解释智能能力与多角色协作；兼顾第一印象和应用价值。
- 纯求职信息门户：检索和列表效率高，但容易淹没高校支持、智能服务与独有品牌，适合后续岗位列表，不宜作为唯一首页风格。
- 纯品牌宣传页：视觉容易统一，但若只有口号、功能宣传和登录按钮，难证明平台可以解决具体问题，不作为最终路线。

## 4. 推荐创意方向：一条航路，连接成长、机会与支持

沿用“每一段探索，都有方向”的品牌主张，以“校园走向职业”的成长航路串联页面。方向感来自路径、节点、留白与视线引导，而不是堆砌灯塔照片或不相关 3D 球体。

候选首屏主标题分两行：**让成长有方向，** / **让机会有回响。**  
候选说明：连接学生、企业与学校，让求职准备、招聘协作和就业支持在同一条路上衔接。  
主行动：**探索就业机会**；次行动：**了解服务路径**；导航右侧：**登录平台** / 已登录时 **进入工作台**。

最终文案需在概念定稿前冻结。在线协作尚未完成时，演示首页须在清晰位置标明“教学演示 · 数据虚构”，不得把候选产品定位写成已兑现的在线服务承诺。

### 4.1 三个有业务含义的识别点

1. **成长航路**：品牌“路/声波/引导星点”转化为贯穿主要区块的克制路径线。节点连接“准备—发现—沟通—确定去向—获得支持”，兼容升学、创业等分支，不把所有学生都推向签约。路径是原生图形，内容保持正常文档顺序，不做滚动劫持。
2. **下一步指引**：访客可选择“找机会 / 做准备 / 需要指导 / 我来招聘 / 校园服务”。点击只解释服务并导航到真实可用入口；不采集简历、不默认记录求职困境，也不伪装成模型推理。学校和管理入口通过统一登录验证权限。
3. **协作接力故事**：用明确标识的同一份虚构申请示例，展示学生授权、企业邀约、学生响应、学校支持、去向审核如何衔接。它解释本项目独有业务链，不展示真实学生、风险标签或看似实时的公共通知。

首屏只保留一个主要视觉焦点；“下一步指引”可置于首屏下缘或下一屏，协作故事在后段，不把三个创意全压在首屏。

## 5. 全页信息结构与布局节奏

| 顺序 | 区域与内容 | 构图/主要交互 | 可见性与真实条件 |
|---|---|---|---|
| 0 | 公共导航：品牌、机会、就业服务、平台价值 | 简洁横向导航，右侧登录；学校/企业说明在对应区块，不堆多个同级按钮 | 发布版本只链接真实页面或本页有效锚点 |
| 1 | 品牌首屏：标题、简述、主次行动、就业场景主视觉 | 约 5:7 非对称图文，路径由校园延伸到机会，浅色为主；移动端文案在前 | 无背景视频、自动轮播、无来源规模数字；控件与文字原生实现 |
| 2 | 机会发现：岗位入口、城市/方向检索、有限精选 | 开放式标题 + 紧凑检索 + 可扫描列表，区别于首屏大图；首批约 4 条 | 上线时来自已审核/有效/允许公开岗位；无数据说明原因，不用永久假数据填满 |
| 3 | 做好下一步准备：简历、岗位解释、面试练习 | 一块清晰的产品预览 + 有限切换，每次讲一个用户问题与证据 | 展示可复现的脱敏示例，注明规则/回放/模型来源；不实时调用付费 AI |
| 4 | 就业服务：活动预告、指导、风险提醒 | 一张重点活动/服务视觉与右侧日期清单，强弱明确；不用整段等大卡片 | 活动/预约未上线时只介绍已可用服务；不制造可点击的报名假入口 |
| 5 | 多角色协作：学生、企业、辅导员/学校、平台治理 | 深色窄幅“接力”区，展示简短步骤与成果条件；说明平台治理而非宣传超管权力 | 客户端示例不连接真实多人数据；企业/学校 CTA 走对应受控流程 |
| 6 | 信任与常见问题：隐私、匹配依据、AI、状态、收费/试用边界 | 简短原则列表与可展开问答，内容可静态读取 | 不放假合作院校、徽章、评价、成功率或“真实 DeepSeek 已接通” |
| 7 | 页尾与收束行动 | 一句行动引导、关键入口、帮助/隐私/条款、品牌信息；内部服务入口低调可达 | 联系方式、运营主体、备案号真实后才展示；设计系统/演示说明不抢公众主导航 |

区块 4 的指导与活动可以合并，避免内容不足时拉出空长页；首页展示少量精选，完整列表承担详细检索。上线范围变化需同时核对导航、文案、按钮和页脚，不能只隐藏一处入口。

### 5.1 首屏与细节约束

- 桌面参考容器宽 1200–1320px、12 栏、24px 栏间距、导航高约 72px；平板 32px/手机 20px 页边距为起点，具体随概念定稿。
- 公共页候选大标题 48–64px，手机 32–40px；正文 16–18px，控件 14–16px。通过公共页专属字阶扩展，不全局放大后台表格与控件。
- 1280×720 保证品牌、标题、说明和主行动可见，不以强制满屏高度挤掉下一段线索；小屏不要求把整张插画压进第一屏。
- 栅格、对齐线、标题断行、中文标点和按钮长度共同校对；字号不靠缩小到难读来迁就布局。
- 搜索框有真实标签、清空、回车提交、错误/无结果；不在占位符轮播宣传文字，不与 AI 聊天混用。
- 卡片只给确有边界的内容，区块间用开放留白、列表、色带和产品局部展示改变节奏；避免“每屏三张同形卡”。
- 岗位展示单位/城市/薪资口径/类型/截止与状态；企业标志仅用获授权素材或文字替代，不生成假认证。
- 日期、按钮、跳转提示与所见页面一致；已失效内容可标明失效，不弹出虚假的成功反馈。

## 6. 与原设计的连续性

| 维度 | 延续与扩展 |
|---|---|
| 品牌 | 复用 `BrandMark.vue`、路/声波/星点和中文名称；不让生成图另造 logo |
| 主色 | 从 `tokens.css` 的白色 `#FFFFFF`、冷浅灰 `#F6F8FC`、品牌蓝 `#2F55C8`、夜航蓝 `#0E1421` 出发；青色表达成长、紫色仅点到智能能力 |
| 主题 | 浅色公共门户为主，深色用于协作/信任重点区并与驾驶舱呼应；若随全站切深色，应适配整页，不能只反色文字 |
| 字体与控件 | 延用本地中文字体栈、间距阶梯、圆角、焦点环和图标体系；大字阶仅作用公共页 |
| 插画 | 校园与职业场景、成长路径、人物协作，轻量有温度；无随机宇航员、霓虹玻璃块或模板式 3D 装饰 |
| 登录衔接 | 公共页主视觉与原登录品牌区呼应；点击登录后尺寸/色彩/按钮习惯延续，而不是风格突变 |
| 工作台衔接 | 登录后切换成办理任务所需的信息密度与侧栏；品牌一致不要求营销首屏复制进后台 |
| 状态披露 | RULE/REPLAY/LIVE 和真实输出来源保持原有可追溯语义，不为了简洁隐藏演示/回退事实 |

动效仅用于按钮反馈、一次路径显现和区块轻入场，优先 120–320ms；不让内容等待动画、不跟随鼠标大幅漂浮，尊重 `prefers-reduced-motion`。主按钮与正文不能依赖光效对比度。

## 7. 公共内容、登录与隐私边界

- 公共浏览不需要先选角色；但当前仓储必须登录才能读岗位，后续应单独定义公开查询投影，不能删除旧鉴权就当完成。
- 公开岗位仅返回被批准公开的业务字段；企业私有联系人、全量候选数据、简历、通知、帮扶、后台审计和私有文件位置不得进入响应/SSR/前端预加载。
- 内部岗位或活动可只返回不敏感摘要，或完全不公开，遵循学校实际政策；不承诺所有高校岗位天然公开。
- 匿名搜索及角色意向不默认持久追踪；仅确有需要时启用最小化统计，并提供必要告知。
- 登录后的跳转目标只允许站内可访问路由并重新鉴权，不能因 query 参数造成开放重定向或越权；网络重试不自动投递/报名。
- 公共展示不能以“全站总人数”等读接口变相泄露敏感小样本；合作机构、评价、成功故事需要真实授权。
- 管理入口不在首屏与学生按钮同权重宣传，但保持可发现；它的安全性来自服务端权限，不来自藏链接。
- 演示模式使用统一可见标识与虚构数据；线上模式没有数据时提供诚实空状态。不存在“正式环境默默回退到演示岗位”的路径。

## 8. 图片与视觉定稿流程

本轮先保存设计策略，不调用付费图片服务。进入正式视觉定稿时，遵循前端设计技能“完整概念先于代码”的流程，并使用用户指定的 `skill-1k` 默认生图渠道；实际调用前重读技能和现行凭据/失败边界，不在本文或交付物保存凭据。

1. 按最终区块编写一致的品牌/文案/原生控件约束，生成首屏及各主要视觉区的可读分区概念，不用一张超长缩略图代替全页设计。
2. 补充移动端、关键展开状态；有复杂岗位/产品示例时单独检查细节。概念图、真实页面截图和投产素材分别命名，避免混淆。
3. 用户审阅后冻结文案、构图、配色、图像裁切、控件和区块顺序，再拆分实现任务。本文尚不是已批准的像素级设计稿。
4. 为首屏/专题单独准备可优化的原创位图资产；品牌徽记、路径线、图标、文字、按钮、真实产品数据与图表仍用代码原生实现。
5. 不从参考网站下载专有图像用于交付；不把整页生图铺成图片热点。不生成假证照、假客户标志、虚构证明或真实学生肖像。
6. 记录素材来源、模型、实测尺寸、用途、裁切和压缩方式。失败/结果不明不自动付费重试，不静默切换供应商。

用户后续补充的 D-20 要求见 `visual-spec.md`：适合场景使用真正接入组件的原创/获授权图片，避免全站生硬单调；相关角色可在获授权模块按需上传、选择、裁切和更换图片。公共首页内容封面必须来自获准公开的素材，上传不自动公开；网络图片需核查许可，截图或裁切不豁免版权。本轮仅记录，素材与上传功能尚未实施。

D-21 全站复核补充见 `visual-unification-review.md`：公共首页企业区、机会列表、内容封面和服务路径应与登录后识别语言连续；不是将相同 logo 卡片复制全页。没有真实热度或授权合作依据，不称“热门企业”或设置合作商标墙；示例真实企业标志不配给虚构企业。该补充仍待设计确认。

## 9. 后续分期与前轮计划的依赖

## 10. 验收清单（后续实施时逐项留证）

### 10.1 入口和功能

- 主网址、`/#/` 等当前有效根入口进入公共首页；登录/未登录都可回到首页；刷新、后退、深链、404 与服务器部署一致。
- 关键用户能快速理解“服务谁、解决什么、从哪里开始”；用户测试中记录实际表现，不预设已达到某个转化提升。
- 每个可见导航/行动有真实目的地；搜索真实筛选，收藏/投递经鉴权；登录返回不丢目标、不自动执行交易动作。
- 正式与演示标识、公开数据、AI 来源和隐私说明准确，不存在虚假合作、成绩或未上线功能宣传。
- 首页可用不依赖第三方模型、追踪脚本、远程字体、图片生成服务或登录后台；必要静态资产本地交付。

### 10.2 视觉和可访问性

- 375/390、768、1280×720、1440/1920 等代表视口检查首屏和全页；中文长标题、空值、无数据和错误态同样设计。
- 对照批准概念与真实渲染截图，至少逐项记录文案、构图、字阶、色彩、留白、图像裁切、容器模型与交互状态的差异并修正；不只验首屏。
- 有可用的主导航、跳到正文、层级正确的标题、输入标签、替代文本、焦点与键盘路径；弹层退出后焦点恢复。
- 普通正文对比度目标至少 4.5:1、大字至少 3:1；状态不只靠颜色；200% 缩放无关键信息丢失；尊重减弱动画。
- 触屏关键目标约 44px；移动导航不遮主要行动；无自动轮播、声音、视频和强制滚屏，慢网络先显示正文。

### 10.3 性能和维护

- 候选性能目标：约定设备网络下 LCP ≤2.5s、CLS ≤0.1、INP ≤200ms。当前未实测，这些不是保证；测试需区分实验室结果与有样本的实际用户指标。
- 主图使用合理尺寸/现代格式并预留空间，次要图片懒加载；重型图表/产品演示按需加载，不让首页下载完整驾驶舱依赖。
- 分区组件、内容数据、公开查询、路由守卫与可复用控件职责明确；避免一个巨大首页组件和复制多套按钮样式。
- 页面标题/描述、链接语义、公开收录策略与隐私一致；不得为了 SEO 公开内部路由和数据。
