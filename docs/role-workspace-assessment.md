# CareerPilot 四角色工作台功能完整性评估

评估日期：2026-11-13（工作区本地日期）  
范围：活动项目源码、冻结需求基线、用户两张参考图，以及成熟平台公开官方产品/帮助资料。  
性质：功能与架构调研建议，不是已批准实施规格；本轮不改业务代码、不部署、不调用付费 AI。

**D-22 实施更新：** 后续用户已授权全链条开发，本机封闭试用实现范围见 `evidence/stage-two.md`。本评估中的“待建设/部分实现”是调研时点状态，不自动代表本期验收结果，也不表示所有候选模块已交付。本期补齐在线身份/归属、收藏、通知、待办、筛选、面试安排、私有工作区图片和异常恢复；预约/招聘会/IM/电子签等扩展仍不纳入。

## 1. 总结：需要从“展示页”升级为“可完成工作的角色工作台”

当前不是没有四角色页面，而是各角色成熟程度不均：学生主链最完整，企业有基础招聘流程，辅导员有统计审核与规则帮扶，管理员主要服务本机演示治理。整体仍是本地教学应用，不能按多用户在线产品判定完成。

完整工作台应回答：我现在需要做什么、为什么轮到我、何时截止、有哪些可用操作、对方做了什么、失败或争议如何处理。统计图只是其中一部分。

本评估采用四种状态，不给没有分母的“完成百分比”：

- **本机已闭环**：有可达页面、命令和状态联动，但不代表在线身份/安全已通过。
- **部分实现**：有基础入口或状态，却缺关键操作、用户响应或异常恢复。
- **仅预留**：仅实体/种子/底层能力，无端到端用户界面。
- **待建设**：当前活动项目未发现完整功能链。

### 1.1 角色总体判定

| 角色 | 已有价值 | 主要短板 | 推荐首页定位 |
|---|---|---|---|
| 学生 | 简历、匹配、练习、投递、协议和去向形成教学主链 | 动态待办、邀约响应、收藏、活动预约、消息与完整个人设置 | 我的求职行动中心 |
| 企业 | 发岗、授权快照、筛选阶段、面试结果、录用意向、协议 | 认证团队、岗位编辑审核、候选检索排序、日程、正式 offer 文书与协作 | 招聘运营工作台 |
| 辅导员 | 辖区名册、去向审核、四类图表、预警帮扶 | 今日队列、多条件筛选、预约指导、独立帮扶档案、定向服务与数据质量 | 学生就业支持工作台 |
| 管理员 | 版本、数据来源、实体数、脱敏审计、演示复位 | 真实账号组织、企业/岗位/活动审核、投诉、内容、数据和运维治理 | 平台运营治理中心 |

### 1.2 与原验收目标的差距，不全是新增需求

冻结 SRS 已有但页面尚不完整的示例：

| 基线 | 代码观察 | 评估 |
|---|---|---|
| FR-S02 首页待办 | `HomeView.vue` 有静态“你的下一步”和当前状态计数 | 尚非面试确认、补件、签约截止等动态任务队列 |
| FR-S03 自动保存草稿 | `ResumeView.vue` 使用组件内草稿和手动“保存新版本” | 当前未见可证明刷新恢复的自动草稿保存；不能把简历版本持久化等同草稿自动保存 |
| FR-S05 分类/类型组合筛选 | `JobsView.vue` 提供关键词、城市、薪资和匹配调权 | 分类、岗位类型等过滤未完整落实 |
| FR-C03 规则匹配排序 | 企业 `applications` 按 ID 排序 | 有匹配快照展示，未成为用户可用的匹配排序/筛选 |
| FR-T01 名单筛选 | `StudentsView.vue` 姓名学号搜索，审核入口优先排列待审 | 不是完整的专业/届别/去向/待审筛选和全流程学生画像 |
| FR-A01 用户角色治理 | `ConsoleView.vue` 只提供固定演示身份切换 | 不具备真实账号创建、授权、禁用、组织分配；不可据旧文档泛称认为已实现 |

这些观察是本轮静态审查结论，不是重新执行所有历史用例后得出的全量缺陷清单。冻结基线不覆盖修改，后续用变更与验收追踪表补证。

另外有两项后续接线前必须注意的语义问题：

- `HomeView.vue` 的漏斗形状宽度由序号固定递减，并非按真实数量编码。建议作为“阶段计数”展示，或改为依据明确事件口径绘制的真实比例图，避免美术形状造成数据误读。
- 企业 `WorkspaceView.vue` 将 `closed` 统一标作“已签约”，而状态机的 `DECLINE_OFFER` 也会产生 `closed`，并用 `closedReason: declined` 区分。接入拒绝 Offer 界面时必须同时修正展示条件，不能把学生拒绝误报为签约。

注意：不复制国外平台的政府证件采集、付费角色层级或海外统计标准；不宣称本项目已对接学信网、国家去向登记、电子签约或学校统一认证。

## 3. 学生：围绕“找得到、投得出、跟得上、能求助”

### 3.1 现状与功能矩阵

| 模块 | 当前状态 | 后续应补齐的能力 | 边界/验收重点 |
|---|---|---|---|
| 生涯首页 | 部分实现：体检、Top3、当前状态漏斗、雷达、静态引导 | 动态待办、未来七日日程、待补材料、邀约/offer 截止、最近消息；每项直接进入办理页 | 数据来自本人，已处理任务消失；日期改用真实业务时间 |

| 消息/个人中心 | 未形成业务闭环 | 业务通知、已读/未读、深链、订阅偏好、资料/意向/隐私、设备会话、投诉反馈 | 未读跨设备一致；关键通知不只靠临时弹窗；敏感消息不出现在公开推送正文 |

### 3.2 首页与信息架构建议

- 首页上方：个人求职阶段 + 最紧急任务；并列显示今日/近期日程，不将体检分固定占据所有状态的第一视觉。
- 中部：精选岗位与“为什么适合”、投递待响应项；下部放个人趋势、指导资源。
- 根据本人主动选择的求职/升学/创业等目标调整内容，不因“少投递”自动否定升学或考公学生。
- 导航分组：行动概览｜求职（岗位、收藏、简历、投递与 Offer、练习）｜服务（活动、预约、指导）｜协议去向；消息和个人设置在全局入口。
- 首批可用版本可把收藏并入岗位、Offer 并入投递、活动和预约并入“就业服务”，避免一次堆出十几个同级菜单。

学生指标以“我应怎样改进”而非分数排名为主：期间投递、有效面试、待回应、offer、可比练习变化。样本不足显示样本量，不以一次面试宣称稳定通过率。

## 4. 企业：围绕“合规入驻、招对人、及时处理、团队协作”

### 4.1 现状与功能矩阵

| 模块 | 当前状态 | 后续应补齐的能力 | 边界/验收重点 |
|---|---|---|---|
| 招聘概览 | 部分实现：在招/进行中/面试/协议计数、管线、待处理数量 | 今日面试清单、新申请待筛、待反馈、将到期岗位/offer、按岗位/招聘周期切换 | 待办可点击定位到人；“待办数量”不是所有时间的面试总数 |
| 企业资料认证 | 种子企业，不是在线入驻闭环 | 主体信息、招聘联系人与归属、必要资质上传、提交/退回/补充/通过/暂停/复核 | 未认证限制发岗；只采集必要资料，不照搬国外证件方案 |
| 团队与权限 | 当前以企业 owner 一人绑定 | 企业管理员/招聘人员/面试官子权限、邀请加入、岗位负责人、离职移交 | 不新增四大业务角色也能内部细分；面试官无需全库候选隐私权限 |
| 岗位管理 | 部分实现：保存后发布、关闭/重发 | 草稿恢复编辑、预览、分类/性质/学历/人数/技能组、审核、修改版本、截止自动关闭、复制 | 当前表单类别/学历等含固定值；发布失败草稿仍需有恢复入口；实质修改需复核 |
| 候选人工作台 | 部分实现：授权快照、阶段操作 | 关键词/岗位/阶段/专业/技能筛选、匹配/时间排序、分页、负责人、待处理时长、可审计备注 | 当前按 ID 排列；不可因匹配低分自动拒绝；不能检索未授权全校简历 |
| 面试管理 | 部分实现：安排时间地点、结果反馈 | 独立日历/列表、邀约学生确认、改期/取消、冲突检测、轮次、面试官评分表、反馈催办 | 底层 RESCHEDULE/CANCEL 能力不等于有页面；内部评价与对外反馈分离 |
| Offer 与协议 | 部分实现：录用意向状态和协议确认 | 模板/条款/薪酬/到岗日期、审批、预览、发出、截止、接收/拒绝、撤销历史、PDF；协议异议和终止 | 当前无独立完整 Offer 文书生命周期；打印采用浏览器/PDF，无需打印机驱动 |
| 校园活动 | 仅预留 | 申请宣讲、报名学校招聘会、参会岗位、展位/时段、候选到访统计 | 企业可申请/承办自己的活动，学校活动需学校审核和资源排程，不无限发布校园招聘会 |
| 沟通 | 待建设 | 先站内业务问询/邀约回复，再按需求建设私聊、附件、举报屏蔽、保留策略 | 首次接触、频率和隐私限制；不向企业公开帮扶、风险标签和练习分 |
| 招聘分析 | 部分实现：当前阶段数量 | 按招聘周期/岗位/负责人看阶段到达、耗时、面试结果、offer 响应、有效渠道 | 曝光/访问率需真实埋点，不用投递数据伪造；自身岗位薪酬分布不代表市场薪酬 |

### 4.2 首页与导航建议

首页采用“近期招聘日程 + 待办队列 + 候选管线”，不复刻学生的成长雷达。候选列表与简历详情用主从布局，状态操作清晰显示条件；需要拖拽看板时仍保留键盘可用按钮。

导航：招聘概览｜岗位｜候选人｜面试日程｜Offer/协议｜校园活动｜企业与团队。消息和设置统一入口，首期可把面试及 Offer 放在候选人详情标签页，业务成熟后再独立。

## 5. 辅导员：围绕“辖区服务、主动支持、审核质量、进展可追踪”

两张图未覆盖该角色，但它是本项目区别于普通招聘站的重要服务端。

### 5.1 现状与功能矩阵

| 模块 | 当前状态 | 后续应补齐的能力 | 边界/验收重点 |
|---|---|---|---|
| 今日工作台 | 未形成独立行动页 | 待审/退回补件、今日预约、即将复查、学生求助、逾期任务 | 默认先看需办理事务，驾驶舱作为分析入口而非唯一首页 |
| 学生名册/档案 | 部分实现：姓名学号查找、去向和材料 | 专业/班级/届别/去向/服务状态组合筛选、学生求职意向、投递服务时间线、授权联系、范围移交 | 辖区分配由服务端决定；关怀记录分层可见，非无限读取私人内容 |
| 去向审核 | 本机已闭环：通过/驳回/撤销、下载材料 | 真正待审过滤、提交时长、补件清单、疑似重复/不一致提醒、前后版本比较、审核历史 | 当前审核路由主要优先排序；机器提示不能替代人工认定；批处理须逐条条件校验 |
| 帮扶管理 | 本机基础闭环：规则原因、创建/复查/关闭 | 独立帮扶档案、学生主动求助、人工判断、责任人、服务计划、到期提醒、复查历史与重开 | 预警消失后仍应可查未结档案；关闭服务不能篡改风险事实；避免污名化标签 |
| 指导预约 | 仅预留 | 可约时段、容量、确认/拒绝/改期、取消说明、记录、跟进与服务评价 | 与学生端同一预约实体；占位并发不可超额；老师私有笔记不直接发给学生/企业 |
| 资源与活动 | 未形成操作闭环 | 指导内容、政策来源、定向推荐岗位/活动、组织报名、到访/反馈 | 推送尊重偏好且可退出；过期岗位不继续推荐；不泄露受助身份 |
| 数据质量 | 未形成独立模块 | 未填报、材料缺失、已签约未登记、已终止仍有效、无归属学生等队列 | 先区分真实待就业、未填、审核中、被驳回、材料不全，而不是都当“未落实” |
| 就业驾驶舱 | 本机已闭环：四图、KPI、八周重放、规则预警、六类本地问数/A7解读、打印 | 届别/专业/班级/时间过滤、下钻名单、授权导出、数据更新时间、明细与聚合一致性 | 算法接口已有部分筛选参数不代表 UI 已接线；自由问数不能绕权限或任意执行 SQL |

### 5.2 首页与导航建议

“今日支持工作台”显示办理队列和预约，“就业驾驶舱”保留深色分析沉浸布局。专业/行业图可点击下钻到获授权名单；每个预警可看到规则、数据时点、人工核实与下一次复查。

导航：今日工作｜学生档案｜去向审核｜帮扶跟进｜指导预约｜资源活动｜就业分析。初期合并“帮扶/预约”为学生支持中心，避免过度分屏。

核心指标：辖区有效人数、材料完整度、待审/超期待审、已审核落实人数、待支持与复查完成、服务覆盖。不要仅按就业率给辅导员制造“强制填报”的激励，也不要把平台外活动缺失误判为学生没有努力。

## 6. 管理员：围绕“平台治理”，不是拥有一切数据

### 6.1 现状与功能矩阵

| 模块 | 当前状态 | 后续应补齐的能力 | 边界/验收重点 |
|---|---|---|---|
| 管理首页 | 本机演示治理页 | 待认证/待审/投诉队列、服务健康、异常/积压、数据更新、可追溯快捷入口 | 不把实体总数当运营成效；面向校园运营的待办优先 |
| 用户与组织 | 演示角色模拟，不是账户治理 | 学生导入与激活、院系/专业/班级/届别、辅导员范围、企业成员、授权/禁用/恢复、审计、交接 | 管理员分超级/业务/内容/审计/运维子权限；防误封、误授权和共享账号 |
| 企业审核 | 无端到端后台 | 待审队列、主体查重、必要材料、通过/退回/拒绝、补充和申诉、到期复核 | 仅资质审核人员访问原件，给原因与改正路径；认证不保证全部岗位可信 |
| 岗位与活动审核 | 无端到端后台 | 发布/变更审核、敏感与误导风险、岗位下架、原因与申诉；活动场地/人数/时段审批 | 下架阻止新投递，但历史申请不能丢；取消活动需通知报名者 |
| 分类字典/规则 | 有数据，无完整维护界面 | 行业/岗位/城市/专业字典及届别期限、版本、停用合并、变更影响预览 | 历史引用不能被硬删；更改匹配权重需版本化和回归，不能偷偷改历史分 |
| 内容公告 | 仅内容实体/种子等预留 | 草稿/审核/发布/撤回、来源、有效期、目标人群、更新记录 | AI 起草政策内容需人工核验；来源失效提示，不冒充官方解读 |
| 投诉反馈 | 无完整闭环 | 学生/企业提交、类别、证据、受理、分派、处理、申诉、回访 | 管理员沟通采用工单；不默认旁观所有私聊；查证访问需授权与留痕 |
| 平台运营分析 | 仅实体数 | 活跃与服务覆盖、岗位有效率、审核时效、投诉处理、跨角色漏斗 | 指标先有口径和真实事件；小样本聚合保护；不能拿平台内录用数冒充全校就业率 |
| AI 治理 | 有本机网关保护，管理页未形成在线治理闭环 | 启用模块/模型、预算、调用来源/失败/延迟、按用户限额、降级、脱敏审计 | 页面不显示 Key；管理员默认只见调用元数据，不默认看完整简历提示词 |
| 系统与数据治理 | 有版本/脱敏审计/演示复位 | 备份恢复、导入导出审批、脱敏、留存、访问审计、运行健康、告警、迁移与回滚 | 正式环境撤出演示复位/模拟身份；看见“最近备份成功”不等于完成恢复演练 |

### 6.2 首页与导航建议

优先用高密度队列表格、批次、筛选、审批抽屉和结果追踪，而不是大面积装饰插画。

导航分组：工作概览｜账号与组织｜认证与内容审核｜投诉工单｜运营数据｜配置治理（字典、AI、审计、系统）。不是每项都要独立一级菜单，按子权限逐步展开。

业务管理员与运维管理员分别关注服务办理、运行稳定性；学校全局就业数据也应按授权提供，不能给“超级后台”无限制原始资料下载。

## 7. 跨角色闭环：页面必须连接起来

| 场景 | 发起与处理链 | 必须覆盖的异常/反馈 |
|---|---|---|
| 企业入驻与发岗 | 企业提交 → 管理审核 → 企业补充/通过 → 发岗审核 → 学生可见 | 驳回、资质暂停、岗位变更复核、下架通知、申诉 |
| 投递与面试 | 学生选简历授权 → 企业队列 → 发邀约 → 学生确认/改期 → 企业面试反馈 | 重复投递、岗位关闭、日程冲突、取消、无回复、权限过期 |
| Offer/协议/去向 | 企业 offer → 学生响应 → 双方协议 → 学生去向 → 辅导员审核 → 统计 | 超时、撤销、双方独立确认、双签冲突、补件、终止后相关去向纠正 |
| 就业支持 | 学生求助/规则线索 → 辅导员核实 → 预约/资源/行动 → 复查 → 结案/重开 | 线索误判、老师调岗、学生取消、复查逾期、敏感记录权限 |
| 招聘活动 | 学校组织/企业申请 → 学校审核 → 企业参会岗位 → 学生报名 → 签到/反馈 | 余位并发、候补、重复报名、活动取消/变更与通知 |
| 治理投诉 | 举报/反馈 → 管理员工单 → 核实与处置 → 当事人响应 → 申诉/结案 | 防恶意举报、证据可见范围、恢复、处理理由和期限 |

业务通知应记录“事件、资源、接收人、深链、发送状态、已读”，事务提交后再投递；重试不能重复通知。业务状态和通知状态分离：已读不等于同意面试，消息送达不等于正式签约。

## 8. 图表科学性与指标口径

先明确人群、时间、去重键、状态/事件、分母、未知值和来源，再决定图形。以下为推荐口径，正式实施时与校方业务定义确认：

| 指标 | 推荐定义/限制 |
|---|---|
| 当前阶段数量 | 某时点各互斥状态的申请数，不叫累计转化率；学生首页现有计数属此类 |
| 投递到面试转化 | 明确一批投递及观察窗口，以去重申请 ID 的首次面试事件计算；撤回/拒绝不抹去历史到达 |
| 面试通过率 | 通过的有效已完成面试 / 有明确结果的有效已完成面试；多轮按“场次”或“人”只能选定一种并注明 |
| Offer 接受率 | 同一发放批次和观察窗口的有效响应，待回复/过期/撤销分别展示；不可混用当前 offer 数作历史分母 |
| 去向落实率 | 按冻结届别/有效学生分母、统计时点、已审核有效且非待就业的去向计算；这是项目口径，不自动等同官方报送标准 |
| 待就业/未填/审核中 | 应区分；当前聚合 `unregistered` 会涵盖多个非通过状态，需拆解后才能指导业务 |
| 招聘时长 | 各阶段事件间时长；仍在进行的流程独立展示，避免仅成功样本导致偏差 |
| 薪酬分布 | 标明城市/岗位/样本数、税前税后/月薪年薪、缺失值；优先中位数与区间，小样本不出可识别人群 |
| 预警与帮扶效果 | 线索可解释、可纠正；服务前后变化不等于服务因果效果；不按风险分给企业自动淘汰 |

每图配数据更新时间、筛选条件、统计说明、空样本状态和可访问的表格/文字替代。趋势不能用固定演示日期伪装实时，曝光量不能凭空生成。

## 9. 共享能力与上线部署的完整性

具体技术策略见 `online-upgrade-strategy.md`。成熟平台的可借鉴之处是可信边界和运营流程，不是照搬复杂架构。

### 9.1 首次封闭试用的最小部署结构

推荐：浏览器 → 同域 HTTPS 反向代理 → Vue 静态资源 / 业务 API 与 SSE → 私网 PostgreSQL + 私有附件存储；业务后端再访问内部 DeepSeek adapter。后台提醒由 worker 执行，提交事件写 outbox。

- 数据库和 AI adapter 不直接开放给浏览器；本机网关配对流程不直接暴露成公网权限系统。
- 配置开发/测试/生产环境、API 基址、允许来源、安全 Cookie/会话、跨站请求防护、限流、CSP 和附件策略。前端环境变量不得含秘密。
- SSE 反向代理需关闭不适当缓冲并配置心跳/空闲超时；多实例前验证事件分发和会话策略，不默认单进程内存广播可横向扩容。
- 导入学生数据先校验字段、重复、归属和预览差异；有权数据源与身份映射确定后再做学校 SSO；试用阶段可以安全独立账号起步。
- 关键提醒先站内通知；邮件需可达性与失败重试；短信、日历 API、地图、电子签均是独立外部依赖，费用及账号另确认。
- 明确数据存放地、个人信息告知/授权、留存和第三方 AI 输入边界；对外部署涉及的备案、学校审批等按实际运营主体核实，不在本评估里宣称合规已完成。
- 配置健康检查、错误与业务审计、AI 预算告警、备份和恢复演练、数据迁移/回滚；日志不得保留密码、Key、完整简历或私密附件。
- 先一套可维护的模块化业务服务，不为技术展示过早建设 Kubernetes、复杂微服务或全量 IM。

封闭试点可先采用管理员审核邀请的少量企业，不要求上线首日就做自动资质核验；但不能取消准入责任。国内高校实际网络、部署区域与第三方服务可达性需在目标环境验证。

### 9.2 所有页面都需要的非理想状态

无账号/无简历/无投递的首次进入；加载/空列表/无搜索结果；无权限/会话过期；断网/同步中/同步失败；重复点击/超时重试；版本冲突；文件上传失败；业务过期/对象被下架；AI 不可用/回退；键盘与屏幕阅读器；移动端长表单和大表格。

这些状态同样属于完整功能与美观验收，不能只设计有数据的成功截图。

## 10. 界面美观提升：统一品牌，不统一成一种页面

本次是功能评估，没有重新运行全站视觉验收，不给美观度分数。后续可执行的方向：

| 场景 | 推荐视觉与布局 | 避免 |
|---|---|---|
| 学生概览/服务 | 明亮、友好、有方向感；行动卡、日历、机会列表；少量就业旅程插画 | 每屏全是雷达/分数；插画挤压待办 |
| 企业招聘 | 清晰高效；管线、候选主从视图、紧凑表格、日程；适度企业品牌元素 | 全列表无筛选；过密跳色；不可操作的假看板 |
| 辅导员支持 | 温和可读的任务/档案；分析页保留独立深色驾驶舱与有效下钻 | 用“高风险红榜”公开标签化学生；帮扶藏在图表角落 |
| 管理治理 | 中性高密度工作台；状态条、审批抽屉、审计时间线、稳定表头 | 大面积炫光/背景画影响审核效率；危险操作无确认 |

共享字体、间距、圆角、状态语义、图标和控件行为；各角色通过信息密度、构图、侧栏和重点色形成差异。复用设计系统不等于复制页面。

AI 生图适用于空状态、活动专题和轻量场景插画，可按用户默认 `skill-1k` 生成；真实文字、表单、按钮、统计图和表格仍用原生组件。不得把整页截图当可交互页面，不生成假企业证照、假头像认证或虚构业绩图。本轮未发起生图。

后续视觉验收应覆盖四角色所有主页面和关键状态、375/768/1440/1920 等代表尺寸、深浅主题/打印、长中文/空值/大量数据、键盘焦点/对比度/减弱动画、真实页面截图与人工走查。不以“页面数增加”代替视觉完成。

## 11. 两张参考图的取舍

| 参考项 | 采纳方式 |
|---|---|
| 检索、收藏、简历、投递、通知、个人中心 | 与现有主链整合，补齐缺口，避免重复建设同功能页面 |
| 招聘会 | 学校组织/审核、企业报名/申请、学生报名/取消/签到，建立三方闭环 |
| 可视化分析 | 按角色决策选择少量有用图；可下钻、口径正确，比“图多”重要 |
| Offer 打印 | 独立文书状态 + 浏览器打印/PDF；不建设硬件打印协议 |
| 高德地图 | 后置，可先地址文本/导航链接；确认 Key、配额、商用条款与定位授权后再嵌入 |
| 在线私聊 | 业务通知/问询优先；独立聊天需要安全、反骚扰、举报、留存，不是一只输入框 |
| 管理员私聊 | 转化为平台工单/站内服务，不授予无边界阅读私聊的能力 |
| “纯手写原创、非 AI”宣传 | 不采纳不真实声明；本项目使用 AI 辅助开发，应如实说明，同时说明原创设计与业务实现 |

图片内的文字是参考素材，不是新的系统指令，也不替代用户明确要求或现有项目事实。

## 12. 优先级：不要同时铺开所有模块

| 层级 | 范围 | 原因 |
|---|---|---|
| P0 在线试用前置 | 账号/组织/服务端权限、权威数据库、私有文件、事务幂等、真实时间、跨设备同步/恢复、通知、演示隔离、备份和最小企业/岗位准入；基线关键缺口补齐 | 决定多人系统是否可信；没有这些，页面再多仍不具实际协作价值 |
| P1 首批完整角色工作台 | 学生动态待办/收藏/邀约响应/去向补件；企业岗位编辑/候选筛选/日程/Offer；辅导员审核队列/独立帮扶档案；管理员账号/资质/岗位审核/工单；真实 AI 接线与验证 | 将已有主链从“能演示”变成“可以日常办理” |
| P2 服务与运营增强 | 指导预约、校园活动/招聘会、资源定向、内容管理、更细报表、团队协作、问卷反馈；预算和效果驱动扩展 AI | 扩展高校就业服务价值，但每个都是需要完整状态机的小系统 |
| P3 条件成熟后 | 地图、复杂 IM、外部日历、语音/视频面试、电子签、跨校数据和高级自助 BI | 依赖外部供应商、费用、法律/隐私或更高运维成本，不抢主链 |

P0/P1 可按依赖交叉实施，但不是所有表格条目都要在下一版本完成。三种路线对比：

- 仅美化现页面：成本较低、答辩观感可提升，但不能满足在线协作和角色服务完整性。
- **推荐：保留当前 UI/领域资产，分期完成在线底座与角色闭环**：改动集中在身份、仓储/命令、协作与缺口页面，资产利用率高；仍需真实联调，不是小改配置。
- 一次全量企业级重做：范围过大、视觉与业务难以同时打磨，试用前风险高，不建议。

## 13. 下一轮应怎样验收

1. 新学生从空账号建简历/草稿恢复，找岗收藏、授权投递；企业另一设备看到且不能看未授权学生。
2. 企业认证未过不能发岗；发布/编辑审核后学生可见；下架保留历史并阻止新投递。
3. 企业发邀约，学生看见完整信息并确认/申请改期；企业反馈后学生得到正确业务提示；已读不能代替确认。
4. Offer/协议双方独立决定，双标签/双设备并发确认仍只有一份有效协议；撤销/终止有完整证据与去向联动。
5. 去向补件/驳回/重提/通过可追踪，辅导员仅见辖区；统计与相同筛选下的明细一致。
6. 辅导员创建帮扶、预约与复查；学生侧看到允许看到的任务，企业看不到敏感记录；预警消失后帮扶历史仍可访问。
7. 管理员禁用/改范围立即影响 API、下载和实时订阅；导出带审计；越权改 URL/ID/请求体不能突破范围。
