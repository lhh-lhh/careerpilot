# 第三阶段封闭试用运行与交付手册

适用Windows / Node24、虚构账号、本机loopback、单进程SQLite。不是公网生产部署说明。真实账号导入、学校字典、TLS/域名、PostgreSQL、恶意文件扫描、留存制度和目标设备/负载未完成，不放入真实敏感材料。

## 安装与初始化

1. 解压源码到独立版本目录；检查release-manifest.json的文件集合、长度、SHA256和securityScan。包不包含数据库、会话、Key、node_modules或Python环境。
2. 运行 `npm ci`、`npm run typecheck`、`npm run build`。需联网取得锁定依赖；离线Demo无需安装但必须预装Node。
3. 设置独立 `CAREERPILOT_DATABASE`，显式 `npm run init:online`，安全保存控制台一次性随机密码。不得把密码贴入聊天、文档或提交；重复初始化拒绝覆盖。已有数据库不要初始化。
4. `npm run start:online`，默认127.0.0.1:4174。检查首页、登录、四角色办理和私有附件。生产TLS未通过前不改变监听边界。

## 备份与恢复

- `npm run backup:online -- <绝对数据库文件> <全新快照目录>`：一致性SQLite backup，包括WAL提交，生成manifest；快照仍包含私有业务与密码哈希，必须受控保存，不进入源码包。
- `npm run restore:online -- <快照目录> <全新恢复目录>`：校验hash/schema/quick_check，拒绝覆盖，撤销所有旧会话，返回恢复库路径。
- 恢复不是合并。快照之后的写入不会自动保留，先停止新写入、保留原库和日志并由操作者核对差异。恢复失败时保留原库，不自动清空或重建。
- 切换数据库后重新登录；核对协议、文书版本、附件、待审去向、通知、收藏、幂等receipt，再继续办理。真实招聘→协议→去向链的本机恢复回归见backup-workflow.test.ts。

## 完整版本切换与回滚

1. 旧版本目录只读保留，新版本独立安装构建；不要覆盖正在使用的dist。
2. 告知用户保存/复制草稿，暂停办理并停止服务；做一致性备份，记录版本、数据库路径、快照时间与hash。
3. 新版本使用明确数据库启动；检查runtime.js在线标识、敏感路径404、AI默认禁用、登录/权限/关键读写。
4. 用户刷新后再继续。旧标签页若懒加载失败，会提示显式刷新而不自动刷新丢输入；此提示不等于无缝发布。
5. 回滚先停新进程。仅在数据库版本兼容时用旧版本访问保留库；不兼容则恢复至新目录，评估快照后写入损失后显式切换。不能盲目降级数据库schema。
6. 本阶段交付验证脚本使用保留的不同旧源码ZIP，执行旧版本构建启动→当前版本→快照恢复并继续工单答复；目标主机的真实发布、异地恢复与监控仍not_run。

## AI与日程边界

同源AI默认关闭；即使服务端开启，仍须逐次脱敏预览和同意。限额为UTC日调用次数，失败消耗预留次数，不自动重试；8秒总超时、256KiB响应、1200输出token、每账号1/全局4并发。真实供应商Key仅由操作者配置，当前没有真实DeepSeek验收。

日程按北京时间显示，单企业账号每场预留60分钟；同企业或同学生的活动安排重叠在事务内拒绝，取消释放时段。不含团队面试官、可配置时长、假期、外部日历或送达保证。文书不是劳动合同/电子签，条款需现实业务核实。
